# Four owner hard gates — acceptance protocol

The existing technical G0–G8 progression remains the source of stage detail. H1–H4 are explicit *human review stops* inserted in the production graph. Separately, Source Quality, Import Quality, Art Quality, Rights, Performance and Release each need honest evidence; success in one cannot imply success in others.

| Checkpoint | Dependencies | Mandatory evidence and real observer | Fail/hold condition |
|---|---|---|---|
| H0 Intake (machine + CTO) | Reference/spec hashes, actual images, rights, permitted tooling | 7 files, consistent identity and scale, target/opcode/actions, analyzed uncertainties, SHA256 of originals | Missing or fake native HD images, inconsistent angles, unapproved design change, unsafe upload |
| H1 Face & Hair | H0; neutral topology source | `face_neutral.png`, `face_wireframe.png`, `face_blink.png`, `face_smile.png`, `face_shout.png`, `face_frown.png`; rig control list; same-lens comparison to owner face; full head/neck topology and hair strands | Faceted/flat face, warped lid, missing 5 independent controls, shape unlike approved reference, plastic tube hair |
| H2 Modular Turnaround | H1 approved; actual source assembly | `front.png`, `side90.png`, `back.png`, `threequarter.png`, `wings_folded.png`, `wings_spread.png`, `bow_detached.png`; UV checker/seam views; LOD budget and object hierarchy reports | Fold/articulation hidden, cloth/feather penetrations, broken UV, prop fused, mismatched identity, wrong scale |
| H3 Rig & Extreme Poses | H2 approved; frozen mesh/rig contracts | Pose test set `shoulder90`, `bow_draw_left/right`, `bow_release`, `wing_fold`, `turn`, `run`; finger socket and bowstring contact; weights and no-missing-bone report; actual FBX reimport and 16 action samples | Clipped bow/wing at any required pose, invalid bone maps, scale drift, missing action/LOD/weights |
| H4 Unity URP / Skill VFX | H3 approved; licensed Editor import | URP material views; `FIRE_ZONE` charge/trail/impact/4x4 visual zone; 10x10 board readability; event-driven normal and reduced-motion video; screenshot contact sheet; player perf metrics with device; `.unitypackage`/prefab/assets verified | VFX masks board, client mutates outcomes, clips not deforming, missing shader/texture, bad lighting, fps/memory not measured, no genuine Unity footage |

Receipts live under `artifacts/character-production/<id>/gates/H1/receipt.json` etc. Write each after generating hashes of actual source/preview files. Suggested receipt keys: characterId, gate, status, artifactHashes, sourceRevision, exactCommands, reviewer, ownerApprovalRef, ownerApprovedAt, blockers, previousGateReceiptSha256, releaseState. `OWNER_APPROVED` requires external owner message/approval, tied to exact hashes. Do not backfill owner approval. If source changes after approval and affects the gate, re-open that gate.

**Before generation**, use the owner's authorization for the specific character, components, credit pool and ceiling. Follow the geometry-first workflow in `source-routing.md` for Icarus V4. The lead reconciles outstanding tasks and available credits before spending.

**Review order:** H1 before H2 before H3 before H4. Workers may prepare independent exploratory parts while waiting, but they cannot promote downstream assets, start a disallowed paid generation job, or claim a subsequent gate passed. CTO may continue unrelated source work. Owner's explicit artistic approval is required at these four checkpoints for this production request; technical CI continues independently.
