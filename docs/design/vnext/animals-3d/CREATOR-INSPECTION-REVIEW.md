# Creator inspection — web review, 2026-11-09

Implementation `225331e`, landscape refinement `4371100`, browser regression `e9fe0ad`, initial-appearance fix `80107b5`. This is a developer technical review of the modular web creator. It is not owner art approval, native qualification or final N06-09 visual acceptance.

The creator now offers **Inspect selected part** and **Whole character**. Face/ear, outfit and tail views use current skinned vertices from the shared 24-bone model. An enclosing sphere, padding and actual camera FOV/aspect fit long/bent rabbit ears and changed poses. Tail inspection turns the character around; other detail views face forward. Explicit whole-character framing keeps the current facing. Resize, pose, LOD and appearance changes update the selected inspection frame. Existing adapters without this optional presentation port keep working and disable the inspection buttons.

The first landscape capture showed the extra panel pushing the part choices below their visible scroller. The compact landscape rule removes explanatory copy and panel padding while retaining both 44px actions. The browser regression asserts that the selected ear choice remains entirely inside its panel after inspection. The original capture is preserved alongside the corrected run; successful interaction tests alone did not catch this visual finding.

Inspection changes only the camera. It creates no new model/texture/animation loop, does not modify appearance or grants, and does not send a server command. Geometry, rig, groom, materials, skin weights, catalog/version and schema remain unchanged. The projection test fits every selected bounding-box corner across three species, three LODs, four poses and landscape/portrait aspects; geometry stays identical and all model leases return to zero.

The live-image probe also exposed avoidable startup work: the creator initialized a legacy default animal, then replaced it with the account draft. It now waits for a valid account-owned draft and passes that appearance into the first constructor. An unavailable wardrobe read creates no placeholder model; Refresh starts the correct saved preview. The existing `setAppearance` call is retained for older factories that ignore the additive initial option; the current factory recognizes the identical parts and avoids a second model allocation. Subscription and loader cleanup remain tied to the editor lifetime.

The initial live-image probe failed without a recorded stage under its default 5s expectation. An unchanged-code retry passed. Three subsequent explicitly functional probes with the existing browser suite's 20s readiness window passed, with uncontrolled navigation-to-preview samples of 5150.2/4006.2/3468.3ms before the initial-appearance fix. These are not the locked loading protocol and cannot establish a p75, improvement or budget pass. The first failure is retained; the 5000ms loading gate is unchanged. Final-source packaged-image results are recorded separately in the acceptance evidence.

The final implementation passes 18 browser scenarios (desktop and mobile emulation), including the failed-read/Refresh/first-appearance case. Final live-image probes pass with exact initial saved parts, preview without a save, secure cookies and deletion of only their own synthetic accounts; uncontrolled readiness samples are 4142.0/2680.2/2856.0ms. No performance improvement claim follows from these warm/cache-uncontrolled samples. The geometry/editor suite initially timed out in three High variant cases while Docker builds/browser tests were active; unchanged isolated execution with one worker passes all 43 under the same 20s case deadlines. The failure and both environments remain recorded.

Browser evidence covers editing every category, preview/reset/cancel without persistence, authoritative Save and Deadline/Maid travel/reconnect, exact retry after a lost ACK, concurrent save conflict, identity switch with a late committed response, WebGL failure and 200% text/keyboard fallback. API evidence separately covers persistence, N/N−1 recipient projection, invalid/incompatible/unowned parts, stale account/catalog/revision, receipts, entitlement revocation, lock-wait session expiry, export and deletion.

Current private captures use fresh `artifacts/vnext/n06-07/browser-*` directories and source-attested `run-*` summaries. The vNext acceptance record carries the exact final run and hashes. Earlier catalog/world/groom captures are preserved.

Open visual findings remain: bright sparse groom/clumps at close range, faceted Low-tier ears/limbs, simple room art, small actors in the whole-floor gameplay camera, and the original controlled cold-loading failures. This camera feature does not resolve those findings or change any locked budget. N06-04 must improve integrated world readability/polish; N06-09 must separately qualify final web art and performance. Browser mobile emulation supplies no physical Android/iOS or human usability evidence. No media was downloaded and no license, public or store approval is inferred.
