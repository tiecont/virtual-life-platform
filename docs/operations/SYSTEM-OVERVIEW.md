# System and traffic observations

System & traffic reads fixed private aggregate and system-owner ports through the operator BFF. It retains the original Overview and gameplay behavior. `GET /api/admin/observations?view=system&range=current` and `GET /api/admin/system-state?view=system&range=current` accept these exact reads only; callers cannot choose a URL, metric query, range, credentials or labels. The BFF authenticates the active operator session before and after cached/coalesced reads. The existing read policy does not require renewed step-up for these aggregate reads; sensitive commands/audit keep their existing elevation gates. Telemetry credentials remain server-only.

Each reader coalesces requests and has a5second fetch budget, bounded body/time and no redirects. Samples are FRESH through10seconds, STALE through30seconds, UNKNOWN after expiry or invalid clocks/schema/source. A failed source may retain a recent sample as STALE; it cannot invent zeros. The browser expires samples locally and requests traffic then system sources sequentially, respecting the API's single-export concurrency guard. Independent source results retain their own coverage and timestamps.

Traffic is process-local, with cumulative HTTP/room counters and fixed-bucket process-lifetime p95 upper-bound approximations. Event-loop histograms cover monitor lifetime. Overflow has no finite bound. Configured architecture edges are separate from observed traffic; totals on one edge do not certify other links, server health or cluster capacity. Dating/internal exports stay excluded and aggregate responses contain no trace/request/room/account/session identifiers.

The system port adds an independent read-only database responding probe, optional local PostgreSQL-pool total/idle/waiting counters, local room-authority diagnostic and expected API metadata/migration/release versions. Expected metadata schema1 and43required migrations are different values, not a claim that schema version is43. Artifact/source revision stays UNKNOWN until an actual artifact source is connected. A SELECT1 response does not certify schema compatibility, replicas, recovery or full DB health; existing readiness/release gates remain authoritative.

Each database source has at most one in-flight checkout/read. Checkout and total read deadlines are1second each; transactions use READ ONLY,500ms statement and200ms lock timeouts. A timed-out checkout retains its pending latch until it settles, destroys the late client and does not accumulate waiters. Failed/timed-out reads destroy their own client; closing the source aborts only its lease. One source timeout leaves other observations available. Minimal supported database ports without counters return UNKNOWN pool fields.

Hospitality owns the aggregate completion-backlog query. It counts undelivered completion/consumer pairs and oldest pending age for the API's configured consumers, including delayed/poison work; it excludes dating and emits no event/account/consumer keys. Zero pending deliveries is observed zero with no oldest age. No configured consumers is NOT_CONFIGURED with null data. These counts do not prove a separate worker is running or cover unknown worker-only consumers. Worker liveness, cluster/deployed artifact versions and platform admission/admitted-player counts remain UNKNOWN/not implemented until their actual sources exist.
