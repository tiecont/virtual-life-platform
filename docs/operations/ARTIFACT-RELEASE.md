# CI artifacts and release candidates

`Quality` runs plan, core, all seven browser groups (including admin) and the final `quality` aggregate on every PR/main push. Core retains the complete integration/security suite. Source, shared dependencies, toolchain, lockfile, workflows and unknown files require all three image builds. Inert docs and K8s/Argo/release YAML/JSON skip the image job; all other required jobs still run. Missing or unexpected skips fail the aggregate. No workflow path filter or skip-CI instruction hides the required check.

The image job runs `node scripts/release-bundle.mjs --output artifacts/release-bundle`. It builds the API, portal and admin from one immutable source snapshot, inspects actual images/SBOMs, runs API and separate generated-certificate TLS portal/admin browser scenarios, saves those tested images and hashes each archive. It uploads image archives for one day and a separate small metadata artifact for 90 days. These expiring artifacts are not a durable archive: archive the candidate/evidence under an approved owner-controlled policy before expiry. Raw generated credentials are removed; raw image-test logs and source contexts are not part of the release bundle.

The separate publisher listens only to completed Quality runs and requires same-repository main push/success, committed `config/artifact-release.json` publishEnabled and `VLP_PUBLISH_ENABLED=true`. Both publishing gates are currently disabled. Before enabling them, verify GHCR package access/private visibility and the exact reviewed main SHA. A workflow file on a local branch does not establish that hosted publishing works. This task does not push the branch, merge, create a GitHub App, publish to GHCR or modify repository settings.

Authorization re-fetches the run/attempt and all required jobs. Fork/PR/other-workflow/wrong-source/failed/skipped image proofs cannot publish. Docs-only successful runs return publish=false. The job downloads only that run's source/attempt-named images, validates all payloads, loads the already tested images, pushes commit/run tags, reads registry content digests and pulls by digest to confirm original image IDs/source labels. Only `packages:write`, `actions:read` and `contents:read` are granted to that job. Login uses the ephemeral GitHub token on stdin; checkout credentials are not persisted and logout always runs. Publishing never changes a cluster or production configuration.

The release directory contains `release.json`, source/run/image check proof, API/web/admin package SBOMs and unsigned project-specific in-toto provenance bound to each registry digest. Schema2 requires exactly API/web/admin with an explicit matching source SHA on each artifact; legacy schema1 API/web candidates remain readable. The current publisher requires the complete artifact set from its committed policy. Worker image publication remains separate work. Schema metadata, migration count/manifest, wire protocol and asset-tree revision are separate fields; current protocol bounds are version1 only, not a new N−1 compatibility qualification. Vulnerability analysis remains NOT_RUN and signed attestations are not claimed. Registry descriptors are fetched independently with Buildx; local Docker image IDs can equal registry OCI index digests on containerd-backed Docker, so equality is not treated as proof or failure.

Run `pnpm release-manifest:check` for policy and every committed `releases/<id>/` candidate; with no candidate it explicitly reports NOT_REQUESTED, not a verified release. Run `pnpm release-manifest:check <candidate-directory>` for local file/hash validation. Before owner promotion use `pnpm release-manifest:check <candidate-directory> --remote`: it requires fresh exact hosted run/attempt/job metadata, the corresponding checked image metadata artifact, and actual registry pulls/source-label matches. Missing/expired evidence, tampered hashes, symlinks, foreign repositories, mutable tags or unreviewed shapes fail closed. Static file validation alone grants no deployment permission.

Run `pnpm release:preflight` to observe current repository enforcement. Current main is unprotected, required checks are empty, rulesets/protection are unavailable with 403, and auto-merge is false. Committed policy keeps auto-merge/production auto-promotion false and owner promotion required. Owner review verifies exact SHA, hosted checks, digests and later staging evidence; this is not technical branch protection. No subscription purchase or repository visibility change is authorized.

For an actual local registry rehearsal run `node scripts/release-registry-smoke.mjs --bundle <verified-bundle> --output <new-private-directory>`. The fixture starts only a disposable loopback registry, loads/pushes/pulls the actual checked images, verifies digest-bound metadata and corruption/mutable-tag rejection, then removes its own container/data. Its manifest is explicitly `local-registry-rehearsal`; normal release validation rejects it. This proves local OCI mechanics, not hosted jobs, GHCR authorization, signed supply-chain assurance or a real deployment.
