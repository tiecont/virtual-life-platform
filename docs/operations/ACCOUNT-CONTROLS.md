# Operator account controls — N07-03 account slice

This is one vertical slice of N07-03. The task remains IN_PROGRESS until event draft/publish/cancel, privacy-workflow status/retention and entitlement-bounded runtime controls also qualify. The existing public/restricted release gates remain closed; no real operator or production account has been changed.

The Accounts tab accepts an exact account UUID, with fresh operator verification. It returns only that identifier, account kind, active/suspended status, control revision, active session count and the existing self-service privacy/receipt policy. There is no account directory, contact/profile lookup, private export payload or arbitrary query. Private player data remains in its owning services.

`GET /v1/operator/account?accountId=<UUID>` and `/account-audit?accountId=<UUID>` require a current operator cookie and fresh step-up. The audit projection contains at most20 command receipts. `POST /v1/operator/account-command` requires the operator Origin, CSRF, fresh session, UUID request key, expected control revision, one action (`suspend`, `resume`, `revoke`) and a fixed reason (`SECURITY_REVIEW`, `OWNER_REQUEST`, `ABUSE_PREVENTION`, `CORRECTION`). Extra fields, SQL/shell commands, free-form private reasons and arbitrary URLs are rejected. The admin BFF applies the same strict schemas and forwards only the operator cookie and allowed headers.

Operator authorization, account/session effects and audit share one PostgreSQL transaction. Lock ordering is operator, canonical account advisory lock, account row; business commands set bounded lock/statement deadlines before waiting for the operator lock. Fresh authorization is checked again before COMMIT. A reused request key returns its original snapshots only for an identical command; conflicting keys or stale revisions return409. The UI retains a request key across an uncertain retry and requires a refreshed account snapshot after conflict.

Suspension revokes all existing sessions and prevents registered sign-in. Revocation alone preserves active account status. Resumption permits new sign-in and never revives a revoked credential. Player HTTP/socket/connected-authority checks remain server-side. Notifications publish only after COMMIT. Duplicate commands repeat no mutation or account-change event; an idempotent transport reconciliation checks current session authority after a lost COMMIT acknowledgement, closing revoked sockets and preserving newly authenticated sessions. Audit failure or expired elevation rolls back account state, revision, sessions and receipt. No reward/event/safety history is erased.

Migration0040 adds default-active account status/control revision and identity-owned immutable command receipts, preserving the first39 migration bytes and one journal. The runtime uses strict40 compatibility; an old strict39 image is not an approved rollback on this schema. No production migration or expanded compatibility claim follows from this additive local implementation.

Audit contains fixed reasons and before/after state, with domain-separated HMAC target references/fingerprints and a keyed hash chain. It stores no raw target UUID, display/contact data, credentials, token, session ID or arbitrary request body. The sole operator subject is separate from player identity. Update/delete/truncate triggers protect ordinary application use; DB-superuser/retention operations are outside that guarantee. Receipts can remain after the account's ordinary deletion without retaining its private profile or a raw target identifier.

Existing authenticated owner export/deletion continues for active accounts, including after an audited resumption. Deletion receipts expire after24h through the existing maintenance path. These controls do not grant an operator private export or deletion authority. A suspended owner's recovery/privacy request needs a separately reviewed workflow; the account slice does not create a credential bypass or claim that broader N07-03 privacy requirement complete. Guest moderation is scoped to its account, not a verified-human ban across new guests. Retention and restricted-owner workflow qualification remain explicit task work.

No physical mobile, hosted release or private deployment is implied.
