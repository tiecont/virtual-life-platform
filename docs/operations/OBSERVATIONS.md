# Process-local observations

`GET /internal/observations` is the version2 aggregate contract for dashboard consumers. It uses the same independent server-side telemetry bearer, empty-query validation,30/minute budget and single pending export as the retained `/internal/telemetry` version1 and Prometheus adapters. These are private read ports; player/operator cookies do not grant telemetry service access. Browser consumers must use an authenticated allowlisted BFF. No token is part of the response.

Each response includes source, schema version, sample timestamp and process start. HTTP/room duration values are explicitly **process-lifetime fixed-bucket upper-bound approximations**. They are not rolling-window p95. The final +Inf bucket yields a null upper bound, not0 or5000ms. Collector rate-window histogram calculations require counter reset handling and actual scrape data; collector installation/staging scrape is N08-02 work. Event-loop values are Node histogram approximations since monitoring began, with their own monitor lifetime and warming/not-started states.

HTTP labels are restricted to11 route groups ×7 methods; room commands use6 fixed commands and17 outcomes. Histogram bounds/count/upper percentile must agree. v2 exports aggregate counters/histograms/gauges only, with no trace/request/span IDs or room pseudonyms. Existing safe tracing remains bounded to128 active spans,100 completed spans and5-minute monotonic retention; dating/internal routes stay excluded. Prometheus HELP and additive v1 durationSemantics label the same existing measurements without changing old values.

A true observed zero is distinct from missing observation. Source failure returns503 without fabricated gauges; clients must show UNKNOWN. DB health, worker backlog and cluster coverage explicitly say NOT_OBSERVED, even though the order gauge performs a bounded database query. An order query is not whole-database health. Source timestamps describe observations, not a server health certification. BFF freshness, topology and live-system UI belong to N07-04; no production capacity claim follows from this endpoint.

`pnpm observability:check` is implemented as a focused real unit/integration lane, covering aggregate projection, overflow, fixed histogram semantics, cardinality flooding/redaction, missing credentials, query denial, actual private HTTP/Socket.IO observations, order-query timeout and independent read budgets. Its execution results are recorded separately from this runbook. No collector, alerts, staging or public endpoint is installed by this slice.
