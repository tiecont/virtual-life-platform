# Standalone portal artifact and runtime origins

`infra/docker/Dockerfile.web` builds the full pinned workspace with `VLP_WEB_STANDALONE=1`, then copies Next's standalone trace, public assets and `.next/static` to a clean Node runtime. Repository-root tracing includes shared package dependencies. The existing combined Dockerfile and normal `next start` build remain available with the standalone profile unset.

The image runs `node start-runtime.mjs` as nonroot `node` in `/app/apps/portal-web`. Provide an exact trusted `API_INTERNAL_URL` and HTTPS `PUBLIC_SOCKET_ORIGIN` at startup. The web process needs no database password, session-signing key, confidential evidence key or operator token. Mount only bounded writable cache/tmp paths when running with a read-only root filesystem.

The `/v1` forwarding destination is read on each request by the framework Proxy, rather than serialized from the build environment. It preserves path/query and uses Next's rewrite implementation; API Origin/CSRF/auth/authorization remain authoritative. Dynamic server pages already read their origins at runtime. Public socket origin is intentionally delivered to the client; internal API origin stays server-side. Caddy continues routing public API/WSS directly to the API using the unchanged trusted-forwarding configuration.

Run `pnpm image:check --target=web`; optional `--source-revision <40-character-SHA>` selects an immutable local snapshot instead of committed HEAD. The checker builds/inspects the web image and verifies a same-source API image, then uses the disposable `infra/compose/image-check.yml` fixture. Only generated-certificate HTTPS is published on loopback; API/web/database remain private. Generated credentials and TLS material are removed during cleanup. Images and private hashes/logs/screenshots remain for inspection.

The executable scenarios cover desktop/mobile browser emulation, secure HTTP-only cookies and identity, actual certificate-verified WSS, forged origins, runtime HTTP forwarding without backend secrets, public asset hashes/immutable caching, private no-store/referrer policy, and restarting the same image with another controlled API/socket origin. Inspection checks trace containment, required server/assets, no backend/development payload, and absence of the build-only API hostname in browser assets. The application package SBOM derives from available standalone package metadata; it does not decompose unversioned vendored bundles or certify OS/CVE coverage. The defined bounded credential scan is not universal secret detection.

[N03-03 results](../architecture/N03-03-WEB-IMAGE.json) record actual local outcomes, same-source image identities and limitations. This preparation does not establish physical-device support, external TLS/domain/cluster readiness, registry publication, public safety staffing or release permission. [ADR 0106](../adr/0106-runtime-web-origin-and-standalone-artifact.md) explains the compatibility choice.
