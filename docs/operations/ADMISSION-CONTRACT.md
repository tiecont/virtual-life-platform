# Admission policy and reference state machine — N09-01

The additive queue/offer/slot contracts and deterministic reference model define future platform admission. They do not add a route, migration, grant allocator, room hook, client queue or runtime activation. Existing API/web/worker behavior remains unchanged. `pnpm test:admission-contract` is implemented and executes actual schema/model tests; durable database races, recovery, UX, capacity and production qualification remain separate tasks.

An account has exactly one reference-model record: WAITING, RESERVED, ACTIVE or RECONNECT_GRACE. Only active+grace+reserved occupy global capacity; their sum never exceeds the effective hard bound. Offering a slot requires occupancy below target, with target≤hard. Waiting/offer/grace deadlines are server-owned and bounded. ACTIVE is not silently forgotten on a timer: durable integration must reconcile/release it against the authority before reuse. Queue size is bounded separately. Technical schema ceilings are not measured sustainable CCU or permission to configure those values.

Duplicate tabs retain one record and the original queue age. FIFO uses a monotonic arrival sequence, including deterministic ties. Offer expiry and missed grace invalidate the old grant; a returning account queues at the tail. Duplicate disconnect does not extend grace. Reconnect transfers the same counted slot, even when new offers are paused or the target is lower; it does not restore room membership, focus time, consent or a revoked session. A current reserved offer becoming ACTIVE does not allocate a second slot. Queue pause stops new offers; world maintenance, safety and entitlement remain independent stronger gates.

Travel and ROOM_FULL/failed room outcomes retain the existing global lease; target room reservations/holds are separate. Lowering target below occupancy produces DRAINING_LIMIT without kicking any record, including while paused; the paused flag remains independent. A requested hard decrease remains pending while occupancy is higher, with new offers held below the new target; it applies only when occupancy fits. Policy changes are versioned. Actual bound increases must later pass N08 capacity evidence and audited N09-04 controls; the reference model is not that authorization path.

Public commands accept request/offer/current-record identifiers and expected versions, with no actor, role, SQL, clock or cap authority. Own-state views reveal only that account's state and position, with no peer/account/room list or fabricated exact ETA. Actor resolution, session revocation, one-time tickets, durable idempotency receipts, SQL locking, fencing/restart reconciliation and version guards on real requests belong to N09-02. The model's allocator-only offer record contains the actor for trusted dispatch; it must never be returned directly to clients. New identifiers come from the trusted allocator, not an enqueue payload.

The model accepts a monotonic trusted clock, rejects regression and bounds UTC serialization. Its maps are a reference oracle, not a shared-process authority or persistent store. Tests cover duplicate tabs/claim, actor/ID collision, FIFO/queue bounds, missed offer/return, grace/reconnect, room-full travel, draining/pending hard decrease and mixed deterministic transitions. Model transition sequences are not actual concurrency, capacity benchmarks or PostgreSQL tests.

Keep global admission unwired until those invariants and downstream client/operational gates qualify. One room owner, existing consent/privacy, strict schema compatibility, release and mobile platform gates remain authoritative.
