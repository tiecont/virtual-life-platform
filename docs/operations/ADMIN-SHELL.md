# Private operator console

`apps/admin-web` is a separate Next application with MFA sign-in, Overview, Audit trail and Session/security views. It uses the [singleton operator service](OPERATOR-IDENTITY.md); player/moderator roles and service tokens cannot sign in. No real operator is provisioned by this slice. Player routes, API/SQL and release entitlements remain unchanged.

Build with the repository's normal `pnpm build`; `pnpm --filter @virtual-city/admin-web dev` and `start` bind loopback3400. API bootstrap/key custody remain on the API side. Configure only the admin server's exact `ADMIN_ORIGIN`, fixed trusted `ADMIN_API_ORIGIN` and optional `ADMIN_METRICS_READ_TOKEN`. The public origin must match API `ADMIN_ORIGIN`; production requires HTTPS. The read token maps to the API's read-only telemetry credential. Omit it for UNKNOWN metrics. There are no NEXT_PUBLIC secret settings, database/cluster credentials or API encryption key in the admin app. Defaults return unavailable and expose no private data. Do not publish these development commands as an access boundary.

The app exposes only `/api/admin/{login,session,step-up,logout,revoke-all,recover,audit,metrics}` with fixed methods. Unknown routes/queries, duplicate operator cookies, forged fields, large bodies and wrong Origins fail closed. The sole metric query is `metrics?view=summary&range=current`; arbitrary PromQL, time ranges, URLs and internal routes are unsupported. Recovery has a guarded backend proxy contract; the initial UI uses the saved operator recovery procedure rather than creating a new account.

Only the exact operator cookie is forwarded. Interactive calls carry no service bearer token or client-supplied authorization/proxy headers. Session-bound CSRF and API validation remain required. Sensitive views/actions require fresh verification. Client cached views clear at their reported idle/absolute deadline without background keepalive; backend expiry/revocation stays authoritative. Sign-in forms use POST even without JavaScript, and inputs clear after authentication attempts.

Metrics use a separate read-only server request,2.5s timeout,128KiB response bound, one in-flight query and at most one upstream query per five seconds per process. Every read checks the session before and after the asynchronous observation, including cache hits. Samples are FRESH for10s, STALE up to30s or after a failed refresh, UNKNOWN after that or when missing/invalid; up to5s future clock skew is tolerated. UNKNOWN values are null and displayed as —; observed zero remains0. Counts are process-lifetime counters or current gauges, not rates, health or capacity. Local UI age checks do not create observations. N08/N07-04 own richer freshness/source/window contracts and dashboards.

Production page rendering creates a fresh CSP nonce per response, requires script nonces and omits unsafe-inline/eval, and sends no-store/noindex/no-referrer/frame denial headers. Development permits Next debugging evaluation; this is not the production policy. The static client guard forbids first-party environment/server imports and is part of `ci:check`. `scripts/admin-bundle-check.mjs` inspects actual production static bytes with explicit synthetic markers through `VLP_ADMIN_SCAN_MARKERS`; missing builds/markers, symlinks, leaked markers and private telemetry paths fail. Marker hashes, file hashes and actual outcomes stay in task evidence; never feed real credentials to this verification.

`pnpm test:admin` includes proxy/crypto and real PostgreSQL/TCP operator cases. `pnpm ci:browser admin` runs four scenarios on desktop and360px mobile emulation, using disposable API/database and development frontend. Actual MFA/snapshot/audit/rotation/revoke flows are separate from explicitly synthetic loading/zero/stale/unknown/error and client-clock fixtures. These are not Android/iOS binaries or physical-device tests. The new seventh group retains all previous30 specs and required aggregate gating. Full typecheck also includes the admin harness/config/specs. Production build and independent local production browser/header smoke are recorded separately.

Disable the private admin endpoint or revert this app for rollback; retain API operator/audit schema and compatible sessions. This task creates no admin OCI image, domain, ingress, public deployment, store release or real operator account. [ADR0117](../adr/0117-private-admin-proxy-and-client-boundary.md) records scope; N03-05 is the exact next image/quality task and N07-05 still requires real private ingress/TLS and release access evidence.
