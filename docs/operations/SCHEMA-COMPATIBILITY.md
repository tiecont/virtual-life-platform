# Schema compatibility and code rollback

`config/schema-compatibility.json` is the current strict39-migration manifest after additive N07-01 operator identity. First38 SQL files are unchanged. Without `SCHEMA_COMPATIBILITY_FILE`, API/migrator derive strict policy from their own SQL. Use only a trusted reviewed image-bound manifest; it loads once, independently of SIGHUP switches.

For a qualified expanded window, preserve the image digest, minimum and every existing checksum; append the exact reviewed migration names/checksums in sorted order, set `mode` to `expand-compatible`, set the maximum to the complete list length, and reference the compatibility evidence. Never use a wildcard version/count or modify historical SQL. The API cannot infer whether an additive SQL change preserves application behavior.

Run `pnpm test:migration-compat` for the local disposable proof. It builds the current committed source by default; `--source-revision <40-character-SHA>` selects another immutable local Git snapshot. The test pins the tracked Dockerfile's Node base to its inspected digest, source-builds the baseline image, creates a synthetic SQL-only expansion image, and checks running/restarted previous runtime, expanded runtime, HTTP identity, authenticated socket, strict rejection, checksum/unknown-history/metadata rejection, and preservation of expanded data. It cleans only its own API containers and the test harness's database. Images and private logs remain under local Docker/artifacts for inspection; the result reports their actual identities.

The fixture appends synthetic SQL after the selected source's manifest; its filename/count follows that manifest. Current39 therefore tests synthetic40. The retained N02-04 [image/scenario report](../architecture/N02-04-SCHEMA-COMPATIBILITY.json) covers its historical38→synthetic39 source only. Neither qualifies arbitrary historical binaries or old38 against actual operator39. Future expand/contract changes require their exact image pair and semantic coverage. Rollback code/config to a qualified image without down-migrating data; unqualified old images remain unready. See [ADR0105](../adr/0105-image-bound-schema-prefix-compatibility.md).
