# API runtime image and same-image migration

N03-02 introduces `infra/docker/Dockerfile.api`. The existing combined `infra/docker/Dockerfile` stays available for historical Compose/recovery/migration fixtures. No production deployment, registry publication or worker entrypoint is introduced.

The new build uses the Node 26.9.0 base digest exercised in N02-04, pnpm 11.28.5 and frozen installation. It builds every application/shared consumer before packaging the API's already-installed production dependency graph with networking disabled. Packaging performs no dependency resolution or download: declared production/optional dependencies and locally bound peers are copied from the frozen installation, preserving distinct peer contexts. Missing required bindings and source escapes fail. Global hoists and unreferenced development packages are excluded.

The build-only CLI accepts only the new `/runtime-api` destination. It copies actual compiled API/shared outputs and removes first-party source/test output. Third-party package contents are preserved; dependency links are rebuilt inside the artifact. Tests exercise a real packaged Node import with a transitive binding, optional/global exclusion, required vendor file retention, first-party source/test removal, no-overwrite, missing binding and escape rejection. The initial legacy-deploy attempt and its cold offline metadata failure remain in task evidence; that resolver-based path is not the shipped build.

The runtime starts from the clean Node base. It contains the API and production dependencies, the unchanged SQL migrations, and bundled default safety/media policy files. It runs as nonroot `node`; application files are root-owned. Package managers and the build workspace are absent. API working directory is `/app/apps/platform-api`; default command is `node dist/main.js`. The migrator uses **the exact same image ID/digest**, overriding the entrypoint to `node dist/db/migrate.js`. It is not a second image or an independently rebuilt migration artifact.

Explicit release/runtime/safety/schema policy files are mounted or injected through their existing environment variables. Bundled defaults remain closed. Runtime switches do not replace release review or secret custody. A separate worker command will be added only after N05-05 supplies a real independent entrypoint; starting another API is not a worker.

Run `pnpm image:check --target=api`. By default it archives committed `HEAD` into a new private build context; `--source-revision <40-character-SHA>` selects another immutable local snapshot. It does not copy the author's working tree, environment files, caches or credentials. The result records actual local image identity, source label, inspection hashes, an application dependency CycloneDX SBOM, command journals and scoped scenario outcomes under ignored `artifacts/image-api-*`.

Inspection executes inside the built image as its configured user on a read-only filesystem with networking disabled. It checks internal dependency links, first-party output, absent development/web packages and package managers, exact source SQL checksums, runtime version and write denial. The credential scan covers defined private-key/token patterns, credential filenames and bounded application dependency text files. It is not a universal secret detector, OS SBOM or vulnerability/CVE certification.

The executable smoke uses a disposable local PostgreSQL instance, production-mode loopback HTTP and real authenticated Socket.IO. It checks missing-secret refusal, empty migration/rerun, session identity, checksum rejection, competing room-owner rejection, SIGTERM exit/socket disconnect, owner release and same-identity replacement. Containers run nonroot/read-only with dropped capabilities and no-new-privileges. Only generated test-owned containers/database are cleaned; images and private logs remain for inspection. Interrupt handling aborts commands and attempts owned cleanup, and any unconfirmed cleanup fails the result.

This verifies a local artifact and a small semantic scenario set. It does not certify TLS/proxy deployment, public safety staffing, external secret custody, capacity or store distribution. Future promotion must use the tested immutable registry digest and exact release set, with its own deployment gates.

The [actual artifact report](../architecture/N03-02-API-IMAGE.json) records the local image ID, source snapshot, SBOM/file hashes, six runtime scenarios, cancellation scope and retained failed attempts.
