# ADR0065 — Documented media readiness never enables playback

M19-05 extends the independently authored all-ages Lounge. Audit found no audio/video/iframe/player,media URL intake or streaming channel. Existing provenance covers original local visual assets;it does not license songs,films or third-party retransmission. All real world/public flags remain OFF. No clearance or provider permission was supplied.

The API loads a strict versioned `config/lounge-media-clearance.json` before constructing the application. It ships empty. Trusted records bind a source SHA256 and rights basis to an exact Lounge event,reviewer,review time,valid-from,expiry,revocation state and matching adapter/origin. A local rights-reference document and SHA256 are mandatory. Evidence must be nonempty,at most64KiB and resolve under `docs/media-clearance`;missing/tampered/malformed evidence fails startup. Hashes prove byte consistency,not legal sufficiency. The owner still reviews the actual rights and scope.

`MediaClearanceGate` accepts up to100 unique event records and eight optional reviewed server adapter declarations. Only `external-https-hls` with an exact credential-free HTTPS origin is recognized;Socket.IO and client-supplied URLs/licenses are rejected. Optional adapter review evidence also requires matching bytes/current dates. Trusted higher-revision catalog replacement checks evidence before changing state;revoked,removed,expired,future,cross-event/cross-world,unregistered/mismatched-provider records cannot return reviewed readiness. Replacement is a server-code seam with no HTTP provisioning route. Catalog changes require a trusted replacement/restart;there is no filesystem watch or arbitrary network evidence fetch.

The actual application registers **zero adapters** and exposes **no playback capability or streaming transport**. A reviewed declaration is only a readiness record,not a provider implementation. Any provider integration needs a separately reviewed/verified delivery,authentication,revocation,privacy and failure contract plus explicit owner/operator approval. No provider uplink or third-party playback is claimed tested here.

POST `/v1/media/view` accepts only schemaVersion/eventId/original Room source. Auth,Origin,CSRF,strict empty query and bounded IP/session limits apply. The existing Audience owner checks listed Event/current original connected Room/world/safety and current scoped moderator/RSVP authority. It returns only internal scope/current permission and a<=3second observation deadline. Other worlds reject404;private IDs reject before Room proof. The public response is always `mode:SILENT,playbackEnabled:false`,with UNAVAILABLE or REVIEWED status and bounded timestamps. No evidence path,reviewer,source hash,URL,peer identity or room proof is returned. It creates no reservation,seat or Stage authority;an ordinary Audience observation header may be created by the shared owner.

Native keyboard controls check status manually with an8second deadline. No autoplay,player,URL input or upload exists. Identity/source/event/hidden/offline changes invalidate observations;local elapsed time subtracts request latency and expires snapshots within3seconds. Strict response parsing rejects a playable or URL-bearing response. Network failure/expiry leaves the silent/text/visual experience usable.

The web shell sends `media-src 'none';frame-src 'none';object-src 'none'` and disables camera/microphone/display capture. The policy applies to every document so client navigation into Lounge does not inherit a permissive source-page policy. It changes no script/connect/image permission needed by existing Room/Pixi flows. This is defense in depth for the current no-media baseline,not a complete CSP/XSS/DRM claim. Enabling any future player requires an explicit header and implementation review.

There is no migration or new account data. Rollback removes the status UI/route and returns to the already silent Lounge;do not weaken CSP or invent rights to make an adapter work. Keep the empty catalog and all release flags OFF until actual owner review. Verification commands/outcomes live in `m19-media-checks.json`;M19-06 fanout/report/emergency drills remain separate.
