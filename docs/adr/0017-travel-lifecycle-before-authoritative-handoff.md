# ADR0017: Travel Lifecycle Before Authoritative Handoff

Status: local model implementation; M09-01 verification is separate from M09-02..06 endpoints, admission, invitations and actual handoff. No world activation.

The audit found one in-memory RoomService owner guarded by a PostgreSQL advisory lock. Account and connection indexes bind one current membership; different-world room.join returns ALREADY_IN_ROOM. Provisional joins currently require that single authoritative membership for registry hooks. Social disclosure is recomputed per viewer, and registry/room/chat apply committed sanctions and incident denial. No travel domain, endpoint, token, reservation or handoff existed at this revision.

Define a strict six-phase lifecycle now, with a fixed maximum30s local preparation deadline, immutable original expiry, monotonic trusted times, expiry before any late preparation/commit, and terminal states that never reactivate. TARGET_COMMITTED is an internal observation of the owner's completed switch, never a browser instruction or a capability. CREATED cannot commit directly. Shared contracts export only the phase vocabulary in this slice; private lifecycle timestamps are not a final HTTP/socket contract.

Preserve the current room.join guard. In the subsequent handoff, source remains the sole active membership while the destination is prepared under a separately bounded nonpublic reservation. READY does not add active presence or authorize normal destination commands. Target authorization/capacity/session/source binding and room owner epoch must be checked again at the actual switch, including current sanctions, incident/base flags, versions, block/consent and reviewed restricted/adult access. Do not call leave then join and call that atomic travel.

The existing one owner can coordinate the eventual index switch without introducing Redis, another owner or a distributed transaction. Durable intent receipts will not make ephemeral rooms durable. A receipt after owner restart is not proof of active target admission; require current epoch/membership reconciliation or truthful lobby interruption. A new durable table alone cannot satisfy handshake acceptance. Implementation and fault injection remain M09-02/04/06.

Scope/rate/idempotency, account/session/source/target binding, one-time durable consumption, HTTP/Socket.IO authorization, reservations/cleanup, multi-tab synchronization and actual network/UI handling are intentionally pending their tasks. Existing trusted-hook nontermination and resource-owning cleanup remain activation limitations; a timer racing an uncooperative hook is not rollback or cancellation. No production migration, legacy import, public flag or privileged identity is introduced.
