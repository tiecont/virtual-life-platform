# ADR0016: Scoped Moderation and Emergency Deny Overlay

Status: local implementation; see M08-05 actual verification evidence. Public release and real staff provisioning remain unauthorized.

Extend current assigned-case/report/sanction services rather than introducing a second staff identity system. The registered scoped expiring DB grant is the server authority; the desk only projects it. Provide conjunctive bounded case filters, privileged assignment, reasoned existing sanction actions and independent appeal read/disposition. The issuer never reads or decides their own appeal; platform appeals need an independent safety-admin. An upheld finding requires authentic nonexpired supporting case/issuance evidence; missing context is not invented.

Use a durable per-world/per-surface emergency deny overlay below registry/chat policy. It remains enforceable and administrable with current trusted staff authentication even when confidential evidence-key access is unavailable. Closing a world drains ephemeral room memberships before acknowledgement; delayed chat publication rechecks the overlay. A second administrator reviews recovery. Clearing an emergency deny never opens base feature flags, restricted worlds or production chat. Preserve the existing single room owner and bounded room queue; do not claim immediate completion when a trusted hook stalls it.

Audit controlled reasons/HMAC actor digests, independently from report-body encryption. Do not expose a grant/self-promotion/break-glass or audit-delete route. Keep independent-review private reasons encrypted and target outcomes controlled. Operate only on synthetic/local fixtures until the owner supplies actual staff/coverage/privacy/contact/retention/public approvals. Metadata retention and resource-owning world cleanup remain explicit activation limits.

See MODERATION.md and operations/MODERATION-RUNBOOK.md for interfaces, recovery and rollback.
