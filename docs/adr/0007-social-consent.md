# ADR 0007 — Private contact codes and transactional social consent

Status: Accepted local implementation design, 2026-11-02. M04 verification pending.

No global user/profile search or unsolicited DM. A player privately shares an unpredictable contact code; a request proves knowledge of that code, not identity/admission authority. Pending outbound requests disclose only state/expiry, never the recipient's nickname, private settings or world. Incoming requests show only the sender's deliberately shared public profile. Accepted friends can see public profiles; activity is omitted unless both platform/world policy and per-world visibility allow it. Dating/unknown-world activity stays hidden regardless of global visibility. Absent room/presence source returns no activity, not a fake offline count.

Normalize account pairs in PostgreSQL. One pending request per unordered pair, one friendship edge per pair. Opposite explicit requests count as reciprocal consent and atomically accept; same-direction retries reuse the pending request. Requests expire after seven days. Accept/decline is recipient-only; cancel is sender-only. Unfriend removes the edge; historical accepted requests never recreate it. Blocks are directional/private but enforced bilaterally for contact: remove friendship, cancel pending requests, notify only affected accounts to refresh without disclosing a block reason. Unblock never restores friendship automatically.

No social authorization cache initially, so policy reads see committed blocks immediately. Internal platform services coordinate identity-account locks in canonical order, then reauthenticate inside the same SQL transaction. Worlds receive service policy ports, never repositories/SQL clients. Explicit UUID Idempotency-Key receipts are scoped to actor and operation/body; no body-provided actor or role. Bound pagination, graph/request counts and per-IP/session rates; persistent rolling request cap survives process restarts. Moderation can subscribe to minimal policy/abuse hooks in M08; no operational moderation claim before that module.

Self settings lazily provision a stable contact code/default code-only request policy under the authenticated account lock. This initialization cannot change existing choices; no global code lookup route. Rotating a code or disabling new requests cancels pending incoming requests. Blocks retain an optional name snapshot only if already known from an accepted friendship or incoming request, avoiding discovery of unknown/hidden profiles.

Retention: pending seven days; closed requests 30 days after original expiry; idempotency receipts 24 hours; friend/block/settings records until removal or identity deletion. Account foreign-key cascades and export-owner hooks cover social lifecycle. These are local implementation policies, not legal approval. Original worlds are untouched; no external contact messages, publishing or public release.
