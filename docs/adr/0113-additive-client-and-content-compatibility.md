# ADR 0113 — Additive client and scene compatibility

Date: 2026-11-06. Status: accepted for the locally verified N05-06 scope; release/device gates remain separate.

Keep application envelopes, snapshots/deltas, identity results and command errors at their existing version1 shapes. Add a public, bounded read-only discovery route `/v1/client-compatibility` and an optional protocol offer on the existing signed-cookie/CSRF Socket.IO handshake. The stable bootstrap envelope remains1; the offer separately declares supported application and scene-schema versions and required capabilities. Current support is application1/scene1, full-snapshot deltas, optional command sequencing and canonical scene-description hashes. Capability metadata does not grant permission, choose an actor or bypass auth.

Legacy handshakes omit the offer and receive no new session event. After current authentication, an incompatible well-formed offer receives `UPGRADE_REQUIRED` with retryable=false and no lease/membership. Origin, cookie signature, CSRF, current-session checks, four-socket limit, IP/session budgets and drain availability remain. Accepted opt-in offers receive `session.compatibility`, bound to the offered nonce. A stale selection cannot activate another stream. The current web client waits for this selection before joining, resets its sequence for a new connection, and sends clientSeq only after support was negotiated. It owns a fresh Socket.IO manager per explicit entry: the installed4.8.4 lookup cache can otherwise retain a manager and its auth callback after close. Automatic reconnect remains within that owned manager with the existing retry/delay budgets. Room snapshots/gaps/epochs and durable receipts keep their previous authority rules.

The client probes discovery with its existing bounded bootstrap request. Only404 selects the legacy adapter; unavailable/malformed/unsupported metadata fails closed with a useful reload/update message. That adapter omits protocol offer, scene identity and clientSeq fields, preserving strict old input schemas. It does not remove Origin/CSRF or introduce native cookie spoofing. Native device sessions/tickets remain N10 work. A server rollback during an already loaded page can require reload/re-discovery; no automatic downgrade follows an authentication failure.

Bootstrap now includes compatibility/hash work, so the entry control stays in the keyboard tab order while loading, with aria-disabled and a guarded handler. A deterministic held-discovery browser case proves that Tab preserves its position, early activation opens no socket, and a later explicit activation after readiness succeeds. Two existing keyboard setups explicitly await enabled before Enter; every original focus/gameplay assertion and performance budget remains. This avoids losing keyboard position or silently treating focus as completed authentication/discovery.

Optional `sceneIdentity` on room.join contains the scene schema version and SHA256 of canonical validated SceneManifest JSON. Object keys sort deterministically; arrays retain order. This identifies the scene description, not sprite/media bytes or license rights. The application protocol, scene schema, scene/world semantic versions, content digest and database migration journal are independent. A mismatched scene schema/hash returns the existing WORLD_VERSION_MISMATCH before allocation. After async hashing, fresh world/session authorization, authority, generation and connection checks run before proceeding. A real pending-hash revoke test must prove no stale ACK/publication. Legacy joins without this field keep the old path and still require version consistency; do not reuse a released scene version for changed content.

The compatibility window here is current opt-in web plus a pre-negotiation wire fixture pinned to `50f10681febb15154d650a2bd13fe9f3d9c97e37`. A source-derived verifier checks its handshake/join/snapshot keys and hashes against that immutable commit. The fixture is not a fictitious released mobile binary or an actual previous-server deployment. There are no distributed mobile builds yet. Wire fixtures, actual TCP auth/room tests and current browser adapter cases establish their stated scope; N12 still owns digest-bound release/rollback qualification.

Socket.IO reconnect/retry is not exactly-once. Resync after a gap or changed epoch/membership before mutating. A retry must preserve requestId/action/payload, including any sequence, and rely on the server's bounded or durable receipt owner. New nonces/sequence streams do not reapply old business effects. Full-snapshot room.delta remains explicit; no sparse-delta or capacity claim follows from negotiation.

Rollback keeps the legacy adapter/window and immutable content versions. Default old-client inputs/responses remain unchanged, but supported distributed builds must be checked before rolling a server back. Keep previous assets and reconcile durable effects; never restore consent or erase receipts to make a retry succeed. All public/store/adult/media/operator gates remain independent and closed here.
