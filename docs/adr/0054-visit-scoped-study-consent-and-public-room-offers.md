# ADR0054 — Visit-scoped study consent and explicit public room offers

M17-04 adds an application-owned Library orchestration service using Room, Event, Focus and Identity owner ports. It owns no account, focus or event table. Sharing is an ephemeral choice for one account/session, exact room epoch/membership and confirmed study event. It defaults OFF, expires at event end or four hours, and resets on process restart. A real room departure, changed identity/privacy, session revocation, contact withdrawal or event RSVP withdrawal invalidates consent. Temporary disconnected visits contribute nothing; a valid same-visit reconnect within the room grace window may resume the original consent.

Consent is an in-memory state machine with opaque revisions and bounded request fingerprints. A new enable must match a revision read from an authorized study observation; stop rotates the revision and remains available outside the room. Old retries observe current state and cannot override a later stop. Pending enable rechecks the revision after owner work. Concurrent same-key enable retries yield one choice. There are at most512account states,64receipts/account,ten-minute inactive/receipt retention and ten-second cleanup. Expired/removed visits fail closed. A failed social/identity transaction may conservatively clear ephemeral consent before rollback; it never restores sharing without a new choice.

The service consumes only phase labels from Focus, never timer IDs, timestamps, durations, task descriptions or rewards. Count only current connected participants who have a valid attached session, current safety permission, confirmed event RSVP, exact matching consent and a profile visible to the viewer under the existing block/privacy projection. The viewer must also opt in. Small-group aggregate counts can allow inference about a consenting visible peer; the UI explains this phase-count audience. Counts are optional, not a productivity score or a promise of continuous presence.

Owner observations are not one distributed transaction. Work is bounded to8global/2account pending operations, with existing HTTP/session budgets and24new enables/account/hour. A result must finish within5seconds from its oldest work start; recheck membership, current consent references, event withdrawal callbacks and safety before returning. Unknown owners fail unavailable. Browser counts expire within5seconds and clear on visibility/offline/source/identity changes. Stop and exact-key retry are explicit. No timer ticks, persistent privacy preference, analytics consent reuse or automatic broadcast is added.

Extend the prerelease InvitationDestination v1 to accept an optional public room UUID. Existing invitations without it are unchanged; strict older readers must upgrade together. Destination already lives in JSONB, so no migration is needed. The room owner verifies public listed world, room/world association, current actor access and versions for send/accept. Offers remain subject to friendship, recipient opt-in, block, expiry and rate limits. A room UUID is a navigation hint, never admission or a reservation. Recipient accepts first, reviews the exact room, then explicitly confirms the existing authoritative travel flow. Full/stale/closed rooms preserve the source and never silently switch rooms. The Library scene can be opened after confirmed admission and reattaches the same visit.

No automatic RSVP, forced movement, group task text, profile/location feed, new media, rewards, operators or public activation occurs. M17-05fulljourney remains a separate gate; real Deadline/Maid integration remains blocked by their source revision boundary. Tests and actual limitations are recorded in m17-sharing-checks.json.
