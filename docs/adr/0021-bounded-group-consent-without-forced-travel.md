# ADR0021 - Bounded group offers and explicit partial consent

Status: local M09-05 implementation; verification evidence tracked separately.

Implement short-lived group invitations as two to four independent offers to friends. Persistent PartyMembership is optional in the module plan and is not introduced: a party is this bounded consent window, with per-person decisions and explicit partial results. A sender cannot move another session or reserve seats while waiting for offline friends. Capacity is checked by M09-04 when each person independently requests travel; groups may split across available rooms. There is no guarantee that the whole group is admitted atomically or seated together.

Group create stores one owner/request/fingerprint, positional entries and a maximum2min common expiry. Each child uses a purpose-separated deterministic UUID key derived from group ID and position, then calls the normal consent/rate-limited invitation port outside a held group transaction. Successful children and linkage are independently durable. If linkage or response fails after a child commits, retry resumes unfinished entries with the original key, preserving the exact child and deadline. SQL/unknown failures propagate; known per-recipient unavailability/rate/pending-pair conflicts become explicit outcomes. No background worker or secret resume token is required. Expired windows cannot issue more children.

Children share the existing six/minute and20/hour sender budget; group creation adds3/minute and max4 recipients. Replayed root input/order must match its HMAC fingerprint. No raw recipient array is stored in group metadata: positional outcomes reference existing private invitations, and unavailable positions carry no peer identity. Only the sender can fetch aggregate/positional results. Recipients receive their ordinary private offer and metadata-free refresh, never group membership, counts, other recipients or locations. Current friendship/block/preference/public-world availability rechecks hide withdrawn child details on group reads/retries.

Migration0011 adds invitation-owned group roots and positional entries. Owner deletion cascades. Peer erasure deletes their ordinary invitation and sets the group reference null, producing UNAVAILABLE without retained peer identifiers. Own export includes bounded root metadata only, omitting peers and input fingerprints. Local24h purge removes roots/entries; retention remains provisional. Rollback closes group routes/UI and retains additive metadata, without touching ordinary invitations or room state.

Tests must cover partial accept/decline/offline expiry, concurrent same-key creation, restart after committed child/link failure, strict input/IDOR/withdrawal/budget/cleanup, and actual group members racing through M09-04 for a single target slot. Browser verification covers native checkbox selection, explicit partial outcomes, live refresh and mobile layout. M09-06 remains responsible for user-facing travel/reconnection/routing.
