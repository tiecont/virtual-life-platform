# ADR 0008: Versioned world modules and guarded local activation

Status: accepted for local implementation; release approval is unchanged.

M05 owns definitions, catalog projection, lifecycle and SDK compatibility. M06 owns membership, capacity, seats, reconnect and room wire envelopes; M09 owns travel. A registry callback is not room admission. SDK hooks require a server-authorized membership reference on every invocation, including onJoin. Until M06 supplies that port, the running API denies every hook invocation. There is no HTTP/socket endpoint exposing SDK dispatch.

Definitions are strict schema/API v1 with exact semantic world/scene versions, declared capabilities including presence, slug syntax, capacity, map metadata and explicit access policy. Private worlds require a policy key. Hidden public worlds and non-hidden/non-adult dating definitions fail validation. Assets are references only; the sandbox does not claim a playable scene or shipped art.

The SDK holds hooks privately. Single-use adapter-bound grants can only be minted after authentication, access and membership checks. Reauthentication occurs after queuing. Each world has a bounded serial queue (64 pending invocations); every invocation checks the captured activation generation and exact world/scene versions. Different worlds have independent queues and flags. Commands never derive account/role/age from payloads.

Disabling marks the world unavailable immediately, rejects queued/new work and drains an in-flight hook before shutdown. Its result is rejected if activation changed while it ran. Hook failure marks that world offline and invokes cleanup; raw exceptions are sanitized. A cleanup failure prevents reactivation until process restart and surfaces on close. This is lifecycle ordering, not transactional rollback: critical commands still require their module's DB idempotency/transaction rules. Trusted hooks must terminate; watchdogs/timeouts remain M21/M22. No uploaded/untrusted code is executed.

Runtime flags are trusted local configuration, distinct from product release signoff in config/rollout.json. All flags default false; only the local SDK sandbox is shipped. Optional WORLD_FLAGS_FILE selects NODE_ENV's flags. SIGHUP reloads without restarting HTTP or other worlds. Invalid/unreadable files or unknown current-environment slugs disable all worlds and report failure. A single bootstrap failure leaves that adapter offline while healthy adapters remain independent. Sandbox activation is forbidden in production. No remote flags/admin-write endpoint exists; operational moderator controls belong to M08.

The catalog requires a valid city session, never lists hidden worlds and excludes private/restricted worlds without trusted policy approval and reviewed adult proof where required. It projects only allowlisted metadata, including truthful disabled/offline availability and a revision for stale-card refresh. Actual presence remains room-owned and independently privacy-filtered.

Alternatives rejected/deferred: remote plugin loading, client/config permission claims, dynamic deployment services and multi-instance coordination. Existing trusted modules and monolith boundaries suffice. No DB migration, legacy modification, asset redistribution or public activation is included. See WORLD-SDK.md for protocol and adapter sequencing. Tests distinguish real HTTP/session/PostgreSQL behavior from controlled membership/access fixtures.
