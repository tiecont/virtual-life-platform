Audit found no backup/restore or DB-volume disk/connection tooling. Keep the existing PostgreSQL17.7 image and city journal; do not touch retained/legacy databases or introduce storage providers. Source selection must resolve exactly one running reviewed Compose DB container by project/service labels and pinned image. No arbitrary database URL, remote host, SQL or shell command is accepted.

Use PostgreSQL custom-format logical dumps with no owner/ACL restoration, consistent snapshot semantics and a5second dump lock-wait deadline. Bound the owned exec process with container timeout110seconds/kill after2more and a120second host CLI watchdog. PGOPTIONS requests60second statement/5second lock waits for probes;dump/restore tools can reset session settings,so this is not a promise that a server query stops at the host watchdog. Encrypt in memory with AES-256-GCM, independent mode600 owner-held key, random nonce and authenticated version header. Enforce64MiB archive limits; no plaintext dump file, credentials or raw SQL diagnostics in output. Fsync and exclusively link mode600 archives atomically;never overwrite. This is a deliberately bounded MVP tool, not a streaming large-database or offsite/PITR service.

Authenticate the entire archive before resolving a restore target or sending any SQL. Restore is permitted only into a uniquely named disposable backup-test project's empty `virtual_city_restore_test` database; never use --clean or destructive down migrations. Use pg_restore single-transaction/exit-on-error. Wrong key, tamper, symlinks, insecure key files, occupied/persistent targets and existing archive paths must fail closed. Backups do not contain runtime session/report/profile encryption secrets; those require separate secure recovery custody.

Observe actual PostgreSQL aggregate connection use/database size and the database container's mounted PGDATA filesystem free/capacity. No query text, account/session/role/data fields enter telemetry. Provide private operator JSON/Prometheus output and documented thresholds, without provisioning a collector or automated production schedule.

Verification must run actual dump/decrypt/restore with durable data and authenticated HTTP session recovery, journal equality, failure guards and disk/connection observations against disposable local databases. Measure local exercise timings; distinguish RPO/RTO targets from achieved guarantees. Real production/offsite credentials, retention, restore authority, scheduling and alert delivery remain operator/release gates.
