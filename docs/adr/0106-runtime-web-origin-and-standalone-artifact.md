# ADR 0106 — Runtime web origin and opt-in standalone artifact

Date: 2026-11-06. Status: accepted; locally verified by [N03-03 results](../architecture/N03-03-WEB-IMAGE.json).

The portal uses Next 16.4.4. Dynamic server pages already read API/socket origins at request time, but the existing external `/v1` rewrite was serialized at build time. That prevented one web image from consistently adopting another trusted internal API origin at runtime. Existing Caddy TLS/WSS routing, API authentication/Origin/CSRF checks, safety headers and default-closed worlds must remain intact.

Use the installed framework's Node Proxy convention only for `/v1/:path*`, returning `NextResponse.rewrite` to the current trusted server environment origin. Assign pathname/query onto that origin; never select a destination from caller headers or a URL parameter. Keep authentication, validation and authorization in the API. This retains framework forwarding instead of introducing a custom HTTP/body/cookie implementation. The installed experimental matcher helper still exports its legacy `unstable_doesMiddlewareMatch` name despite the bundled guide's new name; tests use the actual export without upgrading Next.

Enable `output: standalone` and repository-root file tracing only when `VLP_WEB_STANDALONE=1`. The new Docker build opts in and copies traced runtime files plus the separately required public/static assets. Normal builds and the historical combined image keep their existing start path. The new runtime starts from the tested clean Node digest, nonroot, with startup origin validation and only explicit web configuration. Database/session-signing/report/operator secrets are not web inputs.

Verify the real standalone image with immutable source/image identities, a bounded file/credential scan and actual generated-certificate Caddy/browser tests. Check secure cookies, HTTP/WSS/Origin behavior, asset hashes/cache/privacy headers, and restarting the identical image with different API/public socket origins. Local emulation is not physical mobile or external deployment evidence. Revert the proxy/profile/image slice for code recovery; preserve hashed asset compatibility and separately qualify any real release/rollback in N12. No schema change, world entitlement or public/store authorization is granted.
