Audit: liveness and migration-version readiness already exist. Readiness uses an unbounded pool query and checks only a previously known RoomAuthority state. Two idle replicas can appear ready before either claims ownership. Existing real SIGTERM/SIGKILL tests already demonstrate interruption, fresh epochs and no phantom seats. Main clears schedulers on signals, but has no explicit drain flag or final shutdown deadline. Compose already allows15seconds for stop.

Keep liveness independent of DB. Readiness must coalesce concurrent probes, bound connection/query work, verify the exact bundled migration journal and claim/check the existing single-owner fence. A real PostgreSQL test found that destroying a client after a JavaScript response timeout alone leaves its lock waiter alive. Therefore use a read-only transaction with server-local500ms statement/200ms lock deadlines,plus750ms per-query/1000ms checkout/1500ms HTTP deadlines. Failed reads destroy their checked-out connection; a late checkout is released, never reused for a stale probe. Only committed successful reads return clients to the pool. No periodic new health pool or unbounded queue. Healthy responses remain the existing schema; failures disclose only unavailable. Drain is irreversible per process and immediately closes HTTP/socket admission, then existing owner shutdown hooks interrupt rooms before transports close. No API endpoint allows a player to drain the server.

SIGTERM clears schedulers, begins drain and waits for service shutdown/pool end. A deadline shorter than Compose's15seconds ends uncooperative shutdown with a failing process status, never a success claim. This is one-instance stop/start recovery, not zero downtime or distributed ownership.

Prove local production-mode API replacement, a rejected bad candidate configuration and rollback to an explicitly selected previously built local image with the same migration-file manifest. Preserve the existing independently generated session secret and DB volume. Refuse unknown/incompatible migration manifests before attempting rollback. Do not implement destructive down migrations, production deployment or paid infrastructure. Existing server RoomRecovery tests supply actual joined-room evidence; production flags remain closed in TLS smoke. The runbook must distinguish API rollback, schema compatibility and backup/restore gates.
