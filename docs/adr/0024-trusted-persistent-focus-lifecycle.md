# ADR0024 - Trusted persistent focus lifecycle

Status: local M10-02 implementation; actual checks are recorded in agent evidence.

Implement one engine-owned account timer through strict authenticated HTTP. New start uses a current server-owned epoch/room/member/seat and focus-capable world policy through a RoomService port; caller-supplied role,world authority,clock,completion,elapsed time,reward or notes are rejected. The room owner serializes source eligibility with seat/safety changes. Database work takes account advisory locks, reauthenticates inside the transaction and does not call another pooled service while holding those locks. Focus's trusted callback rechecks synchronous source/generation validity before commit. Replaying a start receipt observes its original timer without granting new room authority.

World definitions opting into focus must provide explicit focusPolicy.pauseAllowed; existing worlds without focus need no change. SDK Sandbox opts into unpausable local focus for testing. This is an additive prerelease SDK evolution for a capability that had no working city consumer; no deployed legacy focus wire/client is silently rewritten. Actual Deadline integration remains M15.

Initial durations900/1500/3000s follow the reference. The deterministic lifecycle has active/paused/completed/cancelled and immutable original duration. Deadline policy forbids pause. Explicitly allowed policies can pause/resume, with a cumulative maximum600000ms pause budget. A paused timer reaching its pause deadline cancels without completion. Exact active end takes precedence over late finish/cancel/pause. Terminal retries never reactivate or award again. Backward trusted clock fails closed. Active reads derive remaining time without writing ticks; client time is not accepted as authority.

Once started, timer persists through leave/seat release/logout/travel/restart as a private account record. Read/commands and bounded maintenance reconcile elapsed timers. Canonical completed changedAt equals trusted endsAt, even if read occurs later; summary date assignment can therefore be deterministic. Completion means elapsed timer,not observed productivity. No economy/award counters or public focus projection are introduced; summaries derive from completed rows.

Migration0012 owns sessions,deterministic creation order,one active/paused partial unique index and mutation receipts. State checks prevent invalid durations/paused/completed timestamps; rows retain source context without foreign keys into ephemeral runtime rooms. Account deletion cascades history/receipts; registered upgrade/login preserves account timer. Own export is bounded to100 plus truncation and omits mutation fingerprints/source membership authority. Durable defaults12 starts/hour and120 new commands/hour/account span sessions; retries do not spend quota. Metadata/history and receipts retain90days in bounded batches,a provisional privacy-policy default. A key can be reused only after retained history is purged; no infinite idempotency promise.

API routes are Origin/CSRF guarded with UUID keys,strict versioned bodies/query/IDs,no-store and bounded request rates. Timer IDs are redacted from logs; no private task text exists in this slice. Rollback closes focus routes/UI integration and retains additive history rather than dropping data. M10-03 adds scoped history/privacy verification; M10-04 timer UI/sharing and M10-05 timezone summaries remain separate unfinished work. Public flags,legacy database/source,staff and remote operations remain unchanged.
