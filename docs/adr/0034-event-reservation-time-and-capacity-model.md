# ADR0034: Event and reservation time and capacity model

Status: Accepted local model implementation. Date: 2026-11-03.

Existing registry already defines events capability but no schedule, RSVP, reservation tables or runtime handlers. Existing focus summaries use PostgreSQL IANA calendar-day arithmetic. Events instead accept explicit UTC millisecond instants plus a validated IANA display zone (or UTC); they do not parse local wall times. This avoids silently choosing an occurrence in repeated DST hours or shifting nonexistent spring times. Intl renders each endpoint with its numeric offset, so the same local clock label remains distinguishable. Database timezone support must also be checked when runtime persistence is introduced.

Strict EventSchedule orders opensAt <= startsAt < checkInClosesAt <= endsAt, within a 24-hour activity window. Creation precedes opensAt. Observation transitions SCHEDULED -> OPEN -> LIVE -> ENDED and may skip elapsed phases. Cancellation is allowed before endsAt; at the exact end the natural ENDED deadline wins. ENDED/CANCELLED cannot reopen; observations and retries do not extend boundaries. Server clock rollback rejects mutation. Recurrence and local-time rescheduling are excluded from this slice.

Reservations are HELD -> CONFIRMED -> CHECKED_IN, with EXPIRED/CANCELLED alternatives. A server policy bounds hold duration to 1..300 seconds and clips it at startsAt. Confirmation at hold expiry fails by transitioning EXPIRED. A confirmed reservation expires at checkInClosesAt; check-in is permitted only in [opensAt,checkInClosesAt), while the authoritative event is OPEN/LIVE. Check-in requires actual room admission in a later runtime task; this model grants no membership, travel or seat. Event cancellation releases outstanding holds, confirmations and attendance allocations while preserving already terminal expiry/cancellation. Natural end preserves historical CHECKED_IN attendance and expires outstanding work. Retry never renews deadlines or reactivates terminal work.

Capacity policy requires literal zero overbooking, 1..100 places, bounded whole-party size and explicit disabled/FIFO waitlist. Active HELD/CONFIRMED/CHECKED_IN parties consume whole party capacity until expiry/cancellation/event end. Capacity arithmetic rejects negative/fractional or already oversold allocations. This pure model is not concurrency evidence: M12-02/03 must serialize each resource in PostgreSQL with uniqueness/transactions, expire under the same lock and verify actual racing requests. Waitlist requires renewed acceptance; it cannot silently grant room admission or force attendance.

Models are private server code with versioned shared vocabulary/schedule/policy contracts. Every runtime action must authenticate and recheck current registry generation, shared safety, event visibility, block and participant/organizer authority; caller-supplied phase is never authority. Private/restricted/dating event discovery, audience moderator approval, notification delivery and operational cancel/reschedule belong to subsequent tasks. No event endpoint, migration, UI, live scheduling, table allocation or public release is claimed by M12-01. Initial missing-model red and actual verification are recorded in m12-model-checks.json.
