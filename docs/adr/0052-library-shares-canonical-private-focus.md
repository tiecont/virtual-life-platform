# ADR0052 — Library focus is an existing engine capability

M17-02 changes Library world version1.0.0->1.1.0 and leaves scene geometry/version1.0.0 unchanged. Enable the public SDK focus capability with an explicit pauseAllowed:true policy. The existing room owner authorizes current account/session/epoch/membership/seat,then invokes the existing FocusService. The existing FocusPanel/FocusTimer handles canonical observations,uncertain replies and user actions. No second timer,account,completion/reward authority,table or tick stream is introduced.

Library pause uses the engine's bounded server pause budget. Deadline's unpausable semantics remain distinct. Account-owned timers continue through leaving,disconnect and API restart;the original Library/room/desk association is immutable. A timer's remaining time is not a claim of measured productivity and is not public room presence. Existing own history/export/erasure and cross-world account exclusivity remain engine responsibilities.

Actual Library tests use eight independently signed Socket.IO visitors in one eight-place room,race one desk and reject a ninth targeted admission. The winner's eight concurrent Fastify HTTP-injection retries create one canonical timer;the browser separately tests actual committed HTTP response loss and exact-key retry. A public presence projection may reveal the permitted profile but never the private timer. Pause/resume/completion and an actual API shutdown/restart use only an injected trusted test clock;there is no public clock-setting endpoint or client completion authority.

No SQL migration,staff provisioning,progression activation,book/note sharing or public flag is added. Local module+world flag gates remain unchanged,with production local activation rejected. Events/quiet group workflows/progress consent remain M17-03..05. Evidence:m17-focus-checks.json. ADR0051's initial scene-only scope remains historical evidence,not a claim that focus was already verified there.
