# ADR0060 — Original silent Lounge and a closed audience stage

Status: accepted and locally VERIFIED for M19-01;all real rollout flags OFF. Actual commands/results: `docs/agent/evidence/m19-scene-checks.json`.

Audit found no Lounge module or stage occupancy owner. The shared SDK already authorizes seats,room capacity and movement from a trusted scene collision manifest. Events already owns canonical schedules/phases,while Hospitality owns future mocktail service. Preserve these owners and create a declarative original Lounge package depending only on contracts/SDK. No other world repository or legacy art is imported.

The all-ages text/visual concept has ten audience chairs in a twelve-place public local room,a decorative virtual mocktail counter and an original closed raised stage. M19-01 stage occupancy is zero:all stage tiles are solid to authoritative audience movement,there are no stage seats and no stage-entry command/role is offered. Unit paths and actual twelve-socket movement/seat/capacity checks verify this closed boundary. This does **not** claim an open one-performer stage,queue,slot expiry or host revocation;M19-02 must introduce those through explicit owner contracts and verify their occupancy separately. Scene perspective or appearance never grants permission. Counter service is closed until M19-03.

The scene schema adds `stage` as a collision kind;existing kinds/manifests and default themes retain their semantics. A new renderer theme draws original geometric curtains,crescent/stars,decorative cups and an audience floor. No audio/video/iframe/player/network media source exists. Current stage surfaces remain silent regardless of the future general Lounge safety context. Existing worlds keep their old geometry/colors. This is a prerelease additive enum for the new world;strict scene readers must upgrade before rendering Lounge. Native room/seat controls remain available on actual asset failure.

The read-only native schedule view consumes Events catalog phases/title/capacity/IANA labels with30second observations,8second deadlines and identity/hidden/offline invalidation. It neither schedules nor assigns performers,RSVPs,rooms,seats or orders. Confirmed empty results are separate from failed or expired observations. Actual trusted scheduling/private filtering/state transitions are integration-tested;browser schedule rows are rendering fixtures. No sample production schedule or operator is provisioned.

Activation requires nonproduction `LOCAL_LOUNGE_WORLD=1` plus an independent registry flag. Production rejects the local option. Browser fixtures install the three original local modules together for compatible scene regressions;real rollout configuration stays OFF. Public Lounge release still requires explicit rights,safety coverage and operator review. M19-04..06 own reactions/RSVP UX,explicit media clearance/expiry and fanout/emergency acceptance. Absence of a media player is not a media-licensing or public-release certificate.

No migration,new SQL owner or alternate session/room authority. Library/Restaurant provenance manifests update the shared renderer source fingerprint without granting release rights. Rollback disables Lounge/local installation and uses the prior app revision;no data downgrade is required. Actual verification and failure history are recorded in m19-scene-checks.json.
