# ADR0037: Scoped event governance and private cancellation

Status: Accepted local implementation; actual verification in m12-governance-checks.json. Date:2026-11-03.

M12-04 adds durable organizer/performer grants, guarded HTTP scheduling/adjustment, voluntary readiness and cancellation notices for supported silent events. Default organizer grants are world-scoped; performer grants additionally bind an event. Both require a current registered account and future expiry. No HTTP grant/self-promotion route or migration provisions anybody. Trusted internal organizer ports remain available for synthetic tests/adapters. Separate current M08 registered/scoped safety grants permit moderator cancellation; organizer/performer grants confer no moderation privilege. Real staff provisioning remains an operator approval gate.

POST events wraps the existing scheduling service with auth/Origin/CSRF/key and registered grant authority by default. POST events/:id/adjust requires the original organizer's current grant and expectedVersion. Adjustments are restricted to an unoccupied SCHEDULED event before opensAt; RSVP/booking/waitlist consent must be absent. Time/zone/overlap checks repeat under the schedule lock. After participation, cancel and create a new event instead of silently moving agreed time. Control version increments on adjust/cancel; automatic time observations do not represent organizer edits. Current policy/generation/deadline guards remain.

GET events/:id/controls exposes viewer-only capability hints, not grant IDs or rosters. Performer-ready requires a current event-scoped performer grant in OPEN/LIVE. Readiness is explicit personal metadata, with no stage/media/chat/moderation authority. Withdrawal remains available after role/world closure for an existing own readiness row. End/cancel clears readiness; M19 must authorize every actual stage command against current permissions rather than cached flags.

POST events/:id/cancel requires the original organizer's current grant or a scoped safety moderator and expectedVersion. It works during world disable/incident closure because it withdraws activity and grants no admission. Natural ENDED wins at the exact end. One transaction changes phase/version, cancels RSVPs, invokes reservation cancellation, clears readiness, stores one unique private notice per participant and persists the mutation receipt. Notice/receipt failure rolls back all effects; terminal retries cannot duplicate notices.

Recipient accounts are locked before event/booking rows to serialize erasure and avoid FK lock inversion. Cancellation snapshots IDs, takes sorted account locks, then verifies the snapshot under the event/organizer lock. A new participant causes a sanitized retryable error instead of a missed notice or reversed account locking; the same request key can complete on retry. Deletion may shrink the snapshot safely. Existing allocation/queue limits bound recipients; no participant identity is exposed to another user.

GET events/notices provides a private durable inbox, bounded100 with truncation. Notices contain ID, already-owned event ID,cancelled kind,time only: no title, private reason, organizer/moderator or attendee list. After commit, connected recipients receive an event.notice refresh hint containing schemaVersion only; exact mutation retries emit no duplicate hint. This is replaceable transport, with the inbox authoritative. Access survives world closure; no email, external calendar cancellation or guaranteed push is implied. Own export includes bounded grant/readiness/notice metadata; account/event90day cascades apply. Notice persistence proves a SQL effect, not human reading. Bilateral block also clears active performer readiness in the social transaction.

Interactive audience remains rejected by the strict schema and SQL constraint. This slice does not implement independent audience approval or open a stage. That fail-closed choice preserves silent scope; M19 must implement/evidence independent moderator approval and operational coverage before accepting interactive events. The earlier handoff proposed that workflow; it remains an explicit future gate and is not claimed complete. Public Lounge/dating/release flags stay OFF; tests infer no real roles/media rights/coverage.

Migration0021 adds event version, scoped grants, readiness and notices with uniqueness/FKs. Existing schedules stay silent; the prerelease view adds control version. Rollback disables governance routes/adapters while retaining data. No destructive down, legacy mutation or public activation. EVENT-OPERATIONS.md documents cancel/retry/reschedule limits.
