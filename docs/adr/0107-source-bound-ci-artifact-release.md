# ADR 0107 — Source-bound CI artifact release with owner promotion

Date: 2026-11-06. Status: accepted; [N03-04 actual local results](../architecture/N03-04-RELEASE-CI.json).

Keep Quality read-only for every pull request and main push, without workflow path filters. Preserve the full core/integration/security and six-group browser lanes. A separate change-plan job decides whether both runtime images are required. The always-running `quality` aggregate requires plan/core/browser success and exactly the planned image outcome: success for source/build/shared/lock/unknown changes, skipped for inert documentation or deployment metadata only. Unplanned skips, malformed outputs and cancellations fail closed. This avoids pending required checks and publish loops without an affected-package optimizer.

Build and exercise API/web once in the read-only runtime-images job, then transfer their exact Docker archives and a small separate metadata artifact. Trusted publication consumes only a completed successful same-repository main-push Quality run, checks the workflow path, source SHA, attempt and every required job, and downloads only that run's named artifact. Registry permission exists only in the separate publisher job; PR workflows receive no package write or credentials. Validate archive hashes, source labels, nonroot configuration and checked metadata before pushing. Publish commit/run tags for discovery, record registry content digests for promotion, and pull those digests to verify the tested local image identities. Never rebuild during publication or use a tag for deployment.

The repository preflight observes unprotected main, no required checks and 403 for rulesets/protection; auto-merge is off. Keep auto-merge and production auto-promotion off with owner promotion required. This process is not technical branch protection. Publishing defaults off in both committed policy and a repository-variable gate. No package, GitHub App, repository visibility, subscription or external environment is changed by implementing this slice.

Release candidates bind source, exact hosted run/attempt, API/web registry digests and local daemon image identities, package SBOMs, image checks, schema/protocol bounds and an asset-tree revision. Provenance is an explicitly unsigned in-toto statement with a project-specific predicate, not a signed GitHub attestation or SLSA certification. GitHub's documented private-repository attestations require Enterprise Cloud; do not purchase it or substitute a synthetic signature. Remote verification re-reads actual hosted jobs, the separately uploaded checked metadata and actual digest-pulled images; self-written PASS JSON alone is insufficient. Vulnerability analysis is explicitly NOT_RUN and requires review before later promotion.

Disable publication through committed policy/repository gate for recovery; preserve verification and previously published digests. Partial pushes can leave orphaned immutable content but cannot produce an accepted release set. Kubernetes promotion, staging evidence, app-bot setup and production authorization belong to later N04/N12 tasks.
