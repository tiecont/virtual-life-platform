# ADR 0005 — Optional offline registered identity

Status: Accepted local implementation, 2026-11-02; API and browser upgrade/login verification passed; see m03-checks.json.

M03 requires an idempotent guest→registered upgrade and reusable login without changing identity. No external identity provider/credentials have been supplied, and owner requests offline work. Implement optional local sign-in name + password, keeping public nickname separate. Guest onboarding remains available. Do not collect email, real name, photos or age documents. Password recovery/email verification is not available and must not be promised; owner-operated recovery policy is a later explicit design, not a hidden bypass.

Upgrade requires active signed cookie, CSRF, exact Origin and UUID idempotency key. It creates one credential for the same account, records a minimal upgrade receipt, revokes prior sessions and issues a new opaque signed cookie. Replaying the original upgrade is safe only while its target session is active. No name/avatar-based account merging and no legacy token import. Login verifies a salted async scrypt digest before issuing any new session or returning an idempotent result. Sign-in names are ASCII-normalized/case-insensitive, passwords are not trimmed or normalized. Input has bounded lengths.

scrypt uses N=32768,r=8,p=1,64-byte output and random 16-byte salt, with explicit 64MiB maxmem. At most four KDF operations run concurrently per API process; excess fails closed rather than queues unbounded work. Unknown accounts also perform KDF work; errors do not disclose whether username/password was wrong. IP/session attempt limits and account session caps apply. These choices require security/performance review before public release; they are not a compliance or load claim.

Credential material never appears in export, public profile, logs, analytics or idempotency payloads. Request fingerprints are keyed HMACs. Login retries use credential verification plus a keyed request record and fresh server nonce; no raw token is stored. A successful account switch revokes the previous browser session after the same transaction. No moderator or restricted-world capability is conferred by registration. Unknown age still denies dating.

Registered accounts persist until explicit deletion under the local policy; expiry removes sessions and temporary receipts, not credentials/accounts. Export includes sign-in name only, never salt/digest. Delete cascades credentials and invalidates sessions. No production data migration or public release. Additive migration 0003 belongs only to platform identity.
