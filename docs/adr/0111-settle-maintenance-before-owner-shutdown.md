# ADR 0111 — Settle admitted maintenance before owner shutdown

Date: 2026-11-06. Status: accepted; actual local checks passed for N05-04.

The existing main entrypoint clears interval handles on SIGTERM/SIGINT, but does not await their already-started Promise chains. Domain close methods await selected domain operations, not necessarily the remaining cross-domain maintenance chain. A continuation can therefore reach a later domain after its close hook or while the shared pool is closing. Keep the current domain/authority/transaction guards and add an orchestration barrier around admitted maintenance.

`RuntimeLifecycle` owns the existing300000ms platform and3000ms service intervals, and SIGHUP world reload jobs. It admits work only while running, skips overlapping ticks of the same periodic chain and tracks its complete Promise. Stop is idempotent: enter draining synchronously, clear future intervals and remove the SIGHUP listener, await admitted work, close the app through its existing hooks (including room interruption and authority release), then close the pool. A failed maintenance invocation retains the existing fixed error log and transaction rollback behavior; it is not a successful business operation. It does not stop unrelated domain work or permit new player work during drain.

The existing12000ms stop budget applies to the entire settlement/app/pool sequence. Deadline or close failure is terminal and makes main exit1. It cannot announce successful drain or begin a later close step after expiry. The helper does not forcibly commit, roll back or release authority ahead of pending work. At the deadline the process exits, so PostgreSQL connection/transaction and advisory-lock cleanup remains essential. An aborted transaction is reconciled through existing durable receipts/outbox rules. This remains a singleton stop/start process, not a lease, distributed fence or zero-downtime rollout.

Existing readiness/liveness, HTTP and socket availability checks remain. DB owner loss is terminal even after connectivity returns; old membership/seat memory cannot be restored. The client must resync and join under the new epoch before mutating. Durable order/reward/visit state must be reconciled from its owner, not inferred from a disconnected ACK. Domain transaction limits, request/handshake budgets, migrations, metadata/protocol versions and public gates are unchanged.

Verification includes actual `main.ts` SIGTERM while its real periodic hospitality read is blocked on an owned PostgreSQL table lock. Releasing the lock permits exit0; retaining it triggers the unchanged12s deadline and exit1. Readiness503/liveness200 and held authority are observed during drain; no owner remains after process exit. Separate real PostgreSQL fixtures verify committed maintenance and progression-outbox effect/receipt settlement, with no duplicate reward after restart. A unique disposable API role is temporarily denied login and only that role's backends are terminated: this exercises actual API DB-access failure, not an entire PostgreSQL server/network outage. Restored credentials do not resurrect the old owner; sockets/epochs must reset. Existing SIGKILL/SIGSTOP/takeover and pending-publication tests remain in the executable runtime-fault lane.

The new `pnpm test:runtime-faults` is implemented before execution; every selected file remains in the normal unit/integration gate. Its process deadline cases have a25s test timeout to observe the real12s stop plus startup/maintenance scheduling. This does not raise the shutdown budget or any existing test/product threshold. Fake-clock lifecycle cases independently cover closure order, non-overlap, signal work, failures and idempotency.

Rollback: revert main's lifecycle wiring and helper independently, preserving recorded evidence. No schema rollback or protocol adapter change is required. Do not run an independent worker via this API composition root; N05-05 still owns durable worker bootstrap.
