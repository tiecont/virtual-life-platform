# ADR0025 - Private world-scoped focus history

M10-03 extends the existing engine API with bounded own-account history,filtered by immutable originating world. The source epoch/member/room/seat is server-owned at start and persists independently of runtime room membership. Moving to another world cannot rewrite origin or start a second running timer. No world reads another world's repositories.

GET /v1/focus/history accepts only optional worldSlug,cursor UUID and limit1..50(default20). Cursor ownership and selected world are checked in the authenticated account transaction. Creation order gives stable descending pagination despite late deadline completion or new insertions. An unknown,foreign,erased or filtered-out cursor returns the same404. A page has at most50 canonical own timer views plus nextCursor/serverTime. Origin scope is a history filter,never an admission token. No database migration is needed beyond0012's account history index.

Privacy follows conservative data minimization: there is no peer focus status/history route,room field,friend activity or automatic shared summary. Public presence in one context does not grant access to private focus data. Global/per-world hidden choices continue to filter room identities. The owner can read/cancel their existing timer after entry closure without authorizing another visit or start. Task text is neither accepted nor stored. Explicit sanitized sharing is separate M10-04 work.

Tests use clearly labeled synthetic Deadline and Library definitions,one unpausable and one allowing bounded pause. They verify actual server seat association,one active timer across worlds,immutable origin,completed/cancelled ordering,strict query/cursor IDOR,hidden/public per-world presence with no focus fields,own export and closed-world denial. These tests do not certify actual legacy or Library gameplay integration. Rollback can remove this additive read route while retaining private history. All rollout flags remain OFF.
