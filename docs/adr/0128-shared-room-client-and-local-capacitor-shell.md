# ADR0128 — Extract the current room client behind explicit platform and presentation ports

2026-11-06. Accepted for local N10-02 preparation; native installation and physical acceptance remain gates.

Move the current room component and its unchanged stylesheet to browser-only `game-client`; keep a small Next adapter at the original import path. The adapter retains Next links and the existing focus, wardrobe, events, invitation and safety panels. Browser identity fetches, cookie/Origin/CSRF, Socket.IO compatibility, authority snapshots, user actions, visit notifications and identity BroadcastChannel retain their existing adapters. Shared code imports no Next, Node or server environment. `client-sdk` supplies explicit fetch/navigation/identity/lifecycle ports; it never persists credentials. Static guards and the build-all map cover the new workspaces.

Vite8.3.5 builds a local `index.html`, chunks and existing public assets. Capacitor core/CLI/Android8.6.0 and App8.0.0 are pinned in the lockfile; the existing N10-01 budgets remain unchanged. Android template Gradle8.14.3 is checksum-pinned, API36/min24 and AGP8.13.0 remain the proposed template pins. Template icons are preparation assets, not approved product branding. No new game-web deployment is introduced.

The installed-origin shell has no authenticated transport yet: it creates no guest, stores no credentials and opens no game socket. It shows a local scene and accessible disabled controls with local navigation fallback. Native login and complete safety/business widgets must be implemented and qualified in N10-03 and subsequent UX tasks before enabling gameplay. Supplying empty widgets in this preview never authorizes a social world. Browser authentication is unchanged.

The existing renderer is CommonJS: Next exposes named exports while a Vite lazy chunk can expose its default namespace. A checked factory adapter handles both. Mobile CSP forbids eval; Pixi's pinned optional no-eval polyfills are imported only through the additive `csp-renderer` entry, leaving the existing Next renderer path unchanged. Do not weaken CSP to make an asset load. Late renderer initialization and failures retain abort/destroy behavior and DOM controls. Lifecycle background invalidates live view, closes transport and suspends the renderer; foreground reloads identity and requires a fresh entry. Browser adapter has no new lifecycle policy.

Actual Linux bundle/browser results are distinct from APK/Gradle/JDK/SDK, physical Android and iOS results. No signing, store upload, distribution flag or N14 activation occurs here. Missing Mac/Xcode/iPhone remain explicit N14 gates; an Android or Chromium result cannot replace them. Keep native gameplay unavailable and preserve the Next adapter until all platform gates pass.

Primary references: [Capacitor installation](https://capacitorjs.com/docs/getting-started), [configuration](https://capacitorjs.com/docs/config), [App lifecycle](https://capacitorjs.com/docs/apis/app), [Vite build](https://vite.dev/guide/build.html), [Pixi optional imports](https://pixijs.com/8.x/guides/migrations/v8). No performance budget was changed after these preparation checks.
