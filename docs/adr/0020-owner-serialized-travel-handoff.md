# ADR0020 - Bounded preparation and owner-serialized travel switch

Status: local M09-04 implementation, verified outcomes recorded in agent evidence.

Travel uses the existing exclusive room owner/schema; it is not a distributed owner protocol. A target preparation hold is separate from all membership/account/connection indexes. Normal join capacity includes active members plus holds (max64 global, original intent deadline). A target adapter explicitly opts into travel prepare/abort/depart hooks; unsupported adapters fail closed. Preparation grants are registry-owned, one-use, adapter-bound and never satisfy normal command membership. The source membership and seat remain active until target preparation succeeds. Other room commands continue while preparation runs outside the owner queue.

Travel hooks receive an AbortSignal and trusted expiry, with a500ms maximum including registry queue wait. Settled prepare failure invokes explicit abort cleanup. Cleanup/departure failure or nonsettling hook quarantines the adapter and forbids reactivation in this process. Timeout releases runtime capacity and never accepts late success; its underlying trusted application code may still be running, so its world requires operator cleanup/restart before resource-owning production use. A nonsettling hook is not awaited indefinitely at shutdown. No automatic resource-cleanup success is claimed for uncooperative code; sandbox/fixtures hold no external player resources.

The coordinator consumes the scoped authorization, prepares a target, persists READY, then enters the owner queue for final source/target/session/epoch/version/safety/flag/capacity checks. Safety mutations already share that queue. In the final account-locked SQL transaction it validates the original row/session, persists COMMITTED target room/membership IDs, and performs one synchronous runtime index replacement before COMMIT. No room departure/join event or target snapshot is published before COMMIT acknowledges. SQL statement/lock deadlines bound transaction waits. Runtime index replacement has an inverse that restores the original source/seat/connections if SQL rejects or acknowledgement is lost; no speculative public membership is broadcast.

The public success point is the acknowledged SQL transaction followed by fresh owner/flag/access checks and target snapshot publication. Observer commands are serialized behind it. Source departure removes all old tabs' authority; only the requesting authenticated connection enters the target, other source tabs receive room.ended and must explicitly reconcile. Identity/avatar remain shared; each target snapshot uses existing viewer-specific privacy projection.

On a definite failed COMMIT the original source remains if still valid. On an ambiguous COMMIT, the database may already contain a historical COMMITTED receipt while runtime restores source. A same-key retry returns that receipt with snapshot:null; it never replays a switch. After restart, old epoch metadata is historical and also cannot restore membership. COMMITTED is not a guarantee of current location. If access/authority is lost after acknowledged commit, target is removed and the result is a truthful null snapshot/lobby; source resources may already have been departed, so source is not fabricated. Source cleanup failure quarantines its adapter; an independently confirmed authorized target can remain active.

Socket travel.request uses strict schemaVersion1/requestId/intentId/capability, existing Origin/cookie/CSRF handshake and fresh per-command authentication, max2 pending/socket and64 coordinator jobs. Retries share an in-flight job only for the same session/key/connection/digest. Different keys conflict. ACK contains a capability-free receipt plus nullable current snapshot. accepted/failed hints contain only schemaVersion/requestId and are sent only to the requesting socket. A historical receipt with null snapshot emits failed, not accepted. No HTTP redemption bypass or query-string capability is added.

Migration0010 adds historical target identifiers and a phase/identifier consistency constraint. Rollback closes travel.request and retains additive metadata; normal room.join still rejects cross-room blind admission. M09-05 groups and M09-06 browser routing/network fault scenarios remain separate tasks. Real legacy adapters, distributed recovery, production external-resource lifecycle certification and public rollout remain gated.
