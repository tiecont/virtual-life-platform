[Evidence](https://github.com/tiecont/virtual-life-platform/blob/cef7dc17172f7c6cda930c99648a5e3ad609cc55/docs/agent/evidence/m22-harness-checks.json),[harness guide](../architecture/TEST-HARNESS.md). Hosted CI/PR/branch protection and real release gates remain NOT_RUN.

Reuse Vitest unit/contracts,sequential per-schema PostgreSQL/HTTP/socket tests,Playwright per-spec/device DB/API/web and existing fail-closed CI groups. Do not scaffold another stack. Audit found that with-test-db spreads parent environment and reuses parent SESSION_SECRET;its URL guard accepts arbitrary schemes/query parameters. A parsed loopback URL with connection-string query overrides must not reach database libraries.

Use strict postgres/postgresql loopback test-name URLs without query/fragment overrides. Generate independent session/report/profile fixture keys and clear inherited runtime/provider/PG settings;preserve an explicit minimal OS/tool/CI/test-toggle environment only. Trusted test commands may still access owner files;this is an environment guard,not an OS/filesystem sandbox. Explicit CI test DBs remain externally owned and are never stopped by the harness. Owned ephemeral databases require local Unix Docker context and generated project names only.

Handle child failures and SIGTERM/SIGINT with bounded owned process-group termination followed by scoped DB cleanup. Never kill arbitrary ports/processes or remove another project's volumes. Error messages must not print URL credentials,parent keys or raw configuration. Actual two-run isolation,nested external reuse,failed child and signal/descendant cleanup must be exercised,not inferred from helper strings. Keep current timeouts/quotas/product authority;record any browser/runtime regressions rather than waiving them.
