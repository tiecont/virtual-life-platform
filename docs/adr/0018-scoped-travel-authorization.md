# ADR0018 - Scoped durable travel authorization before handoff

Status: accepted local M09-02 implementation. No public activation.

The existing room owner remains the only membership authority. A travel intent is authorization metadata, not a reservation, READY admission or a room change. Issuance and trusted internal redemption ask that owner to validate the exact source epoch/membership/session and current target access, versions, capacity, sanctions and incident controls. The future M09-04 switch must revalidate those conditions at its own linearization point; the interval between an observation and a database write grants no membership authority.

Persist one active intent/account, original maximum30s expiry bounded by session expiry, scoped account/session/owner/source/destination, hashed capability and body-free mutation fingerprints. Account advisory transaction locks and a partial unique index serialize creation/cancel/redemption. Same request keys observe the same current intent; altered input conflicts. A redeemed key retries only its own redemption. Restart invalidates the prior owner epoch; expiry and terminal phases never reactivate. New intent creation is capped at6/account/minute in retained storage.

The capability is a purpose-separated HMAC derived through the identity secret, with only its hash persisted. The original create retry can reproduce it before consumption/expiry; ordinary GET and account exports cannot. Redemption has no public HTTP endpoint. No capability is accepted through a query string or put in request logs. Rotation of the identity secret invalidates authorization; production key rotation remains an operational gate.

Migration0008 adds travel-owned intent/receipt tables and indexes. Session/account deletion cascades; own exports include at most100 capability-free receipts and an explicit truncation flag. Expired/terminal metadata is deleted after24h in bounded maintenance batches; this is a local engineering default, not an approved privacy policy. Operational retention/holds and production approval remain gates. Roll back the application by closing travel entry points and discarding outstanding authorization, retaining additive tables; do not drop user data or run down-migrations automatically.

Current tests exercise real PostgreSQL, HTTP/TCP creation retries, socket source membership, concurrent one-time redemption, restart, quotas, source loss, session isolation/logout, private/adult/flag/capacity/safety denials, exports/deletion and transactional receipt failure. These tests do not establish actual handoff, party capacity, invitations, public release or a distributed room protocol.
