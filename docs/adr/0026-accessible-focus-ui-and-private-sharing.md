# ADR0026 - Accessible focus UI and explicit sharing

M10-04 adds a small reusable React package,focus-ui,depending only on contracts and React. It owns accessible timer presentation and sanitized completion text,not HTTP/session/room authority. Portal supplies a separate controller using the existing focus API. This package is added to the workspace boundary allowlist; no world repository import,second focus engine or new framework is introduced. Installation uses the local pnpm offline cache.

The existing SDK Sandbox scene remains the real inspectable visual context. A native DOM section below seat controls offers15/25/50minute radio choices,start,policy-gated pause/resume,cancel,refresh and retry. Controls remain usable with motion reduced and no sound. Timer digits use a stable tabular region with role timer/aria-live off; phase/command outcomes announce only meaningful state changes. Presence and timer are independent: leaving a room does not cancel the persistent timer. No active seat disables only a new start.

Display countdown derives from the latest trusted remainingMs with monotonic performance time; browser wall-clock overrides cannot complete the server timer. At zero the UI requests a canonical observation and shows completion only after the API confirms. Visibility/focus/online events and a30second visible-tab refresh reconcile sleep/other tabs; there are no per-second server writes or tick broadcasts. Explicit request failure shows unconfirmed time. Each controller lifetime owns abortable fetches,listeners,bus and interval; identity replacement unmounts old private projections. HTTP commands retain a single in-memory UUID/body across interrupted responses,blocking conflicting writes until retry. Canonical retries observe the original durable server receipt.

Sharing is local,explicit and reversible. Only a confirmed completed timer enables an initially unchecked completion-summary choice. The generated text includes elapsed duration only; no account,nickname,date,world,room,seat,task text,URL or token. Copy requires a separate user command; nothing auto-posts to friends/feed or a third-party service. The choice resets on timer change,uncertainty and remount. The engine does not accept/store task text. A share card here is a private DOM preview and copied plain text,not a public publication endpoint or an image upload.

Actual acceptance uses desktop/mobile Playwright with a real HTTP response aborted after its DB-backed start,original-key retry,reload/visibility recovery and a clearly marked local test-only persisted deadline fixture for completion. It also verifies keyboard controls,reduced motion,no per-second live announcements,44px targets,no overflow,opt-in summary/no identifiers and logout cleanup. No15minute browser wait or actual productivity proof is claimed. Pause rendering follows explicit policy; actual Deadline/Library integration remains gated inM15/M17. Rollback removes the additive UI/controller while private persistent timers remain available via API. All public world flags stayOFF.

The expanded suite exposed an old invitation assertion that assumed no earlier test had ever allocated a room. A valid empty persistent runtime room can remain after focus leaves. The assertion now compares room catalog before/after invitations and checks both invite participants still have no membership,so accepting an offer still cannot teleport or allocate occupancy. Runtime cleanup and timeouts are unchanged. A redundant concurrent build hit Next's build lock; a later sequential full build passed. Both failed logs are retained.
