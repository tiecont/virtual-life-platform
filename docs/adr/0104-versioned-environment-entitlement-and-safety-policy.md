# ADR0104 — Versioned environment entitlement and runtime safety

Status: accepted for implementation, 2026-11-06 (Asia/Ho_Chi_Minh). Scope: N02-03. Current real release approvals remain absent; no deployment or principal is provisioned by this decision.

The legacy runtime installs real worlds only through explicit development/test flags. Its v1 safety schema requires false approval fields and unassigned escalation, and production deliberately disables evidence/chat. Removing those checks or changing their false literals would erase the historical offline boundary. Keep that profile and its tests intact; add an explicit versioned environment profile.

`RELEASE_POLICY_FILE`, `RUNTIME_WORLD_POLICY_FILE` and `RELEASE_ENVIRONMENT` select the new profile together. It cannot mix `WORLD_FLAGS_FILE`, `LOCAL_*` or synthetic dating-proof controls. Staging uses production runtime mode; development/test must match their runtime mode. An optional `SAFETY_POLICY_FILE` supplies reviewed rules; otherwise the original bundled v1 rules remain the default.

Git-owned release entitlement pins the environment, version, curated world installation/entitlement/version, canonical safety-policy hash, capability ceiling, review references and one operator secret reference. It is immutable for that process. Changing it requires rollout/restart. Runtime policy can only operate within that bound and must name its release version; malformed/missing/unknown/stale or conflicting same-revision input disables all installed worlds. Identical replay is idempotent. Runtime policy is currently a file-backed adapter with monotonic revisions within one process; durable DB policy, authenticated writes and audit remain N07/N09 work.

Only curated real factories are installed, without sandbox/fixture overrides. World version pins must match the actual adapter. Registry activation and use have separate policy ports: content can bootstrap before becoming usable, and direct internal `setEnabled(true)` cannot bypass effective entitlement. Captured projections, authorizations and prepared admissions invalidate immediately on withdrawal; cleanup/Leave remain independent. No new room owner or database is created.

Safety v1 remains a strict historical false-only contract. Safety v2 keeps all existing confidential-retention, report access, bounded content, independent review and no-automatic-sanction invariants. Reviewed responsibilities reference the same single operator secret, with an HTTPS appeal contact. Its exact parsed rules must match the release hash. A confidential capability requires its own safety/operator review even when worlds are closed; social-world entitlement requires confidential reports and a configured key before installation. Production activation also requires the versioned public-safety review and explicit release references. Runtime maintenance cannot turn off existing confidential receipt/review access merely by closing worlds.

V1 of the environment model supports bounded canned/emote interactions in Maid/Park under the same current permission/block checks. Quick interaction permission is rechecked before publication, including after asynchronous work. Production free text and live media remain unsupported; real dating installation and Lounge entitlement remain closed. Legacy local/prototype tests retain their earlier scope and behavior.

Exactly one human operator reference replaces the idea that six historical responsibility labels require six humans. This is a configuration requirement, not implemented MFA/bootstrap, a live account count or fabricated staffing. N07 must enforce the actual principal/authentication constraints. Review references are trusted GitOps inputs, not cryptographic attestations of a human decision. N12 must qualify the exact candidate, operational coverage and actual approvals; a valid configuration or fixture cannot grant public release.

All committed current entitlement, runtime and safety defaults remain closed, with no operator reference or review approval. Positive tests use explicitly synthetic references, keys/accounts and disposable loopback SQL/HTTP/Socket.IO. They prove code paths in production mode, not TLS deployment, real human approval, MFA provisioning or public readiness. The historical release decision/trains and their strict governance assertions remain labelled offline fixtures; current environment validation is `pnpm release-policy:check` in the root quality gate.

Rollback the profile/code independently while keeping effective worlds closed. Preserve historical SQL, payload schemas, operator-independent enforcement and consent withdrawal; no data down-migration is required.
