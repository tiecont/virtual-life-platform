# ADR 0108 — Compatible optional room command sequencing

Date: 2026-11-06. Status: accepted; [N05-01 actual checks](../architecture/N05-01-PROTOCOL.json).

The existing room protocol already has strict version1 schemas, authenticated actor context, room/membership/owner epoch checks, actor-scoped action/payload fingerprints, bounded five-minute receipts, server-computed movement and roomVersion-based resync. Durable order/reward/travel mutations already use transactions, uniqueness and reconciliation. Preserve these adapters and semantics instead of introducing a parallel command wrapper or changing historical migration/fingerprint formats.

Export a strict common `CommandEnvelopeSchema` with the existing schemaVersion/requestId fields. Add optional integer clientSeq in 0…2147483647 to owned room commands. Seat, movement and leave check it within the existing global owner queue after current session/membership authorization and receipt lookup. Only a fresh sequence greater than the last accepted sequence on that connection/membership may apply another mutation. Gaps are allowed; ordering does not guarantee delivery. A matching receipt returns current state without reapplying the effect, even after a later command or a lost projection/ACK.

Store accepted watermarks on the private member object, keyed by active connection. This preserves them when a failed durable travel commit restores the exact source member; recreating counters from a connection index during compensation would lose this ordering. Repeated same-connection joins keep the watermark. Detach, session revocation and member removal clean it up. Reconnect/new membership uses a new stream after authoritative resync. Do not persist ephemeral watermarks in SQL or weaken epoch validation.

Inputs without clientSeq retain the existing adapter. This optional field is an ordering aid for capable clients, not an authorization boundary or an exactly-once guarantee. Existing product clients remain unchanged; capability negotiation and supported N/N−1 clients belong to N05-06. Snapshot reads remain available for resync without advancing the mutation watermark. Chat explicitly keeps its previous strict shape and independent moderation/receipt flow. Use the existing IDEMPOTENCY_CONFLICT error for stale ordering; do not change old ACK enums or global schema version.

Keep one PostgreSQL advisory room owner and global serialization. This change does not optimize the queue, turn snapshot-carrying room.delta into a sparse delta, implement a worker, qualify production capacity or distribute native clients. Rollback this additive code independently while no product client requires it; future rollout must honor its declared supported-client window. Historical SQL, durable request fingerprints and public/safety entitlements stay unchanged.
