# ADR0120: purpose-bound privacy access for suspended owners

Date: 2026-11-06. Status: accepted for the second N07-03 vertical slice; the composite task remains incomplete.

A suspended registered owner must retain a privacy path without restoring player authority. Identity owns a separate request credential, password proof and export/deletion ports. Existing active-account self-service and guest expiry remain intact. No privacy token authorizes player HTTP, Socket.IO, operator access or a different request purpose.

The owner proves their password to create a pending export or deletion request. A fresh MFA operator reviews only minimal request metadata, with an explicit ownership-check attestation and UUID reference to a private review. That reference records a manual review; the software does not authenticate an external case or certify legal identity. Approval binds the current account control revision and password credential, lasts at most 15 minutes and cannot outlive the seven-day request. The owner then supplies the privacy CSRF token, exact request identifier and password again; deletion also requires explicit confirmation. Only the owner receives the generated export. The service stores no export copy.

Reuse the existing bounded password-hashing pool, identity account lock and operator transaction boundary. Request/effect/audit commit together. Erasure calls existing domain owners and deletes the account under the same transaction. Lost deletion acknowledgement reconciles canonical authority; retry returns the private receipt without repeating erasure. Review retries return their original snapshot without extending approval. A later account control or changed password invalidates earlier approval.

Use domain-separated HMACs with the existing session secret for request tokens, CSRF, credential bindings, login buckets and audit references. Store only the token hash and a random request nonce; identical creation retries can reissue the same token after a lost response. Production cookies are separate host-only Secure/HttpOnly/SameSite Strict credentials. Operator projections and audit contain no owner profile, sign-in name, password, token, CSRF or export payload. Audit uses a keyed request reference; fixed actions/reasons and before/after metadata are chained through a digest head.

Migration 0041 is additive, preserving the first 40 SQL files and the single journal. Strict 41 compatibility is required. Request access ends at retention time even if maintenance is unavailable. Pending requests last seven days; completed/denied/closed receipts last 24 hours; audit rows last 30 days by database clock. The tracked minute maintenance purges at most 100 expired rows per table per tick. Audit updates/truncation and premature deletion are rejected; expired deletion preserves the digest-head anchor. This guarantee excludes a database superuser. No automatic down-migration or old-image compatibility widening is approved.

Durable per-name failure buckets, per-account request budgets, operator review budgets and HTTP IP/global budgets bound abuse. Retention cleanup and owner access are independent of operator provisioning; approval fails closed without the singleton operator. Real review staffing, production migration, private deployment, public release and mobile distribution remain separate gates.
