# ADR0069 — Isolated native DateRoom and private contact safety

M20-04 extends the synthetic-only logical matcher with a native timed private conversation. Real rollout flags,all eight adult/product/operator/legal approvals and the provider remain closed. This prototype is not a real dating pilot or human age-assurance/safety assessment.

An accepted proposal authorizes only its exact two original account/session participants to inspect WAITING date controls. Each must separately choose conversation with approved canned messages. Two current explicit choices activate a private DateRoom,clipped to the original accepted lease and current proof/session/profile authority,never more than300seconds. It is a dedicated restricted.dating aggregate,not a generic social Room,world directory,travel target,Socket.IO room or public avatar/presence projection. A native keyboard/mobile interface is the scene for this closed prototype;there is no Pixi dating world or world-travel claim. Generic dating Room.list/join/travel are denied even with positive adult-world policy. Generic reviewed-adult travel elsewhere remains supported through a separate adult-fixture regression.

The matcher exposes a private accepted-pair transaction port. Its existing positive mutex→bounded captured sorted accounts→proposal order remains authoritative;date rows/receipts follow the proposal lock. Every date command validates both original sessions,current finite profiles/proof/safety/block and immutable deadline again after awaited SQL. Final downward authority clipping updates the returned scope. Negative Leave reuses matching Stop and needs no positive key/flag/proof/reporting availability. Existing profile edit/withdraw/expiry,Social block,account erasure and recovery terminate the shared proposal then date in the original transaction,without acquiring new peer/global/Room owner locks. Date-close failure rolls back initiating profile/block changes. In-memory recent messages may be discarded on an attempted rollback;they are a volatile observation,never durable delivery history.

Authenticated gateway liveness observers read only handshake context synchronously;positive commands still reauthenticate against the current session DB. Observers are attached only to explicit test-only dating prototype configuration and ignore guests. Session connection generations are server UUIDs,persisted separately for both date consents. Last original-session socket loss removes its generation and schedules owner-only negative termination. A remaining tab of the same session retains it. Reconnect creates a new generation and cannot restore former date consent,even if the asynchronous negative operation fails or runs late. Its callback compares the lost generation and cannot end a later explicit new date generation. API process epoch changes also interrupt dates;accepted proposals without any date consent retain the M20-03 lifecycle. There are no dating payloads on sockets.

Only configured approved hello/thanks/need-help/bye keys can be sent. SQL receipts store random message IDs,HMAC fingerprints and quota metadata,never canned content or raw text. Durable per-account limits are one new message/two seconds,20/date and60/hour;old-key retries add no feed entry. After receipt commit,a volatile feed keeps at most20messages/date and100feeds,until the original deadline. Receipts mean recorded,not delivered;Leave,expiry or current restriction may win before the peer reads. Manual authenticated observations expire within3seconds after subtracting request elapsed time. A chat incident/mute is checked again after receipt awaits. Room-eject sanctions from private Date evidence scope to that Date ID,and recovery ends the original consent permanently.

Shared Reports gains a strict private-date provenance variant. Only an authenticated original participant of a started date within24hours of first date entry can resolve its subject internally. No current adult eligibility,positive feature flag,public profile visibility,friendship or unblocked contact is required to report. The Safety owner encrypts allegations and applies its existing quotas,case assignment/conflict checks,review/audit/appeal/retention rules. A report creates no automatic sanction. A private block resolves the peer internally and uses the existing pair-locked Social owner/callbacks for platform-wide denial. Migration0035 adds social_blocks.disclose_target(defaulttrue for compatibility). Trusted private blocks suppress new peer IDs/labels in general lists,exports and general friendship notifications;normal explicit general block contracts remain intact. Existing independently known public friendships/blocks cannot be retroactively hidden. Opaque private block management remains a later privacy/operations review item;no public pilot is approved.

The UI separates matching acceptance from conversation consent. Independent native Leave/block abort and fence held positive replies;report remains available after an observed active date ends or eligibility is lost. Leave/block have separate IP/session transport budgets,so exhausting positive checks/messages cannot consume their allowance. Profile withdrawal remounts matching/date descendants. Unknown writes keep their exact original key/body in component memory. Private IDs,choices and messages do not enter URLs,localStorage,analytics,global profiles or notifications. No photos,free-text interaction,voice/video,media,contact exchange,rewards or automatic friendship is added. Reports use a fixed empty note in this prototype;human reviewers see trusted contact provenance,not an invented transcript.

These are unreviewed local defaults,not legal retention or backup-erasure guarantees. Rollback disables positive prototype installation while preserving independent Leave/block/report/withdraw/export/erasure and compatible SQL history. An older enabled binary must not run against active dates it cannot terminate.

Negative receipts describe their original request. In particular,a private block retry must not undo a later explicit general unblock or claim that its historical receipt proves current denial. The UI labels it recorded;another fresh block is an independent choice. The original date remains ended throughout.
