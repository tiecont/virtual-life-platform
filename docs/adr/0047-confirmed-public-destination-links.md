# ADR0047 — Navigation hints require explicit authoritative travel

Status: local implementation; actual checks in m14-route-checks.json.

Travel accepts a strict public destination slug and optional room UUID from Next's awaited searchParams. Unknown keys,arrays,malformed values,room-only links and authority-bearing input produce a generic invalid-link state without reflecting their contents. URI fields are navigation hints, not identity,role,proof or capabilities. Public world cards and at most3anonymous rooms from the authorized activity directory link to confirmation. SDK's direct local-scene preview remains available and its join guard refuses cross-world movement.

Opening a link never creates an intent or admits a room. Only an approved available public catalog world enables Confirm. A specific room stays explicit in the existing TravelDestination contract; server checks world/room association,current permission,source epoch/session and capacity. Manual world changes clear the room hint. Existing selected room/world is not re-entered; a different room in the same world uses the same authoritative handoff. A stale/foreign/full room never silently falls back to another room. The actual source stays until target admission succeeds.

Validated query navigation owns a fresh client lifetime. In-memory pending proof is not placed in URI/storage or carried as arbitrary query data. Server own-room hydration determines the actual visit after explicit navigation,including ambiguous prior work. Link input cannot choose another account's source. The existing backend API/schema/migrations are unchanged.

HTTP requests now have an8second client deadline as well as lifecycle abort; Socket.IO retains its existing5second acknowledgement deadline. Interrupted operations retain exact mutation keys for explicit retry. Transport copy does not contradict a subsequently confirmed source visit. A known created intent can be closed durably via its owner API; confirmation and cancellation remain source-safe.

If the HTTP receipt never arrived, the UI cannot truthfully claim server cancellation. It offers Dismiss interrupted request and explains waiting briefly before another trip. The unseen CREATED authorization has no redeemed travel command or destination hold and retains the existing <=30second engine expiry. Dismissing clears only local pending state; a new trip may be rate/conflict blocked until expiry. Actual tests distinguish this from a known receipt's durable CANCELLED phase.

Real browser cases fill a2place room using independent signed Node/Socket.IO actors,verify exact source membership retention on ROOM_FULL,release one place via actual room.leave,then admit the requested room and transfer within the same world. Hidden/invalid/closed and foreign-room links fail without disclosure/admission. Dropped outbound travel command verifies durable cancel; held actual HTTP reply verifies bounded busy state and truthful unknown dismissal. Existing lost HTTP/commit ACK,reconnect,multitab,identity and snapshot-expiry regressions run separately. No real-world adapter,adult access,operator provisioning or public rollout is activated.
