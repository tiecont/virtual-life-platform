# ADR0085 — Owner-selected offline legacy snapshots

Status: Accepted for offline integration,2026-11-05.

The owner explicitly confirmed:“Tôi có quyền; dùng snapshot hiện tại trong bản sao riêng để tích hợp offline.” This selects the current working source of Deadline and Maid,including their uncommitted/untracked implementation,and authorizes local code/asset reuse in a separate copy. It supersedes ADR0001's requirement that the original active repositories themselves become clean commits before adapter work. Original repositories,histories,working changes,processes and databases remain untouched. This instruction does not authorize public release or grant an external media license.

Capture the selected non-generated source/configuration/docs/assets in independent clean Git snapshots. Store portable Git-generated archives and SHA256 manifests under `integrations/legacy-snapshots`;keep private snapshot Git metadata and editable runtime copies under ignored `artifacts`. Archives preserve original dependency locks and toolchain declarations without importing either project into the city pnpm workspace. There are no source-tree symlinks. Exclude real environment files,credential configuration and generated compiler caches;do not copy node_modules,builds or databases. Keep example environment templates as source inputs without printing their contents.

The snapshot verifier checks archive/entry/source hashes,commit metadata,bounded sizes,regular file types and safe paths before materialization. It rejects links,traversal,corruption and existing destinations. Capture refuses to replace a selected snapshot. Independent Git commit/fsck and executable snapshot tests establish the pin;no legacy server/DB/runtime test is implied. Initial script lint failures are retained and corrected. Existing legacy audits remain historical observations,with this amendment supplying their formerly missing owner selection/reuse scope.
