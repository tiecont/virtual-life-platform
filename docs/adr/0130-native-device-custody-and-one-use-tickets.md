# ADR0130 — Native device custody and one-use socket tickets

Status: accepted for the bounded N10-03 implementation, 2026-11-07. Implementation and verification remain separate. Android is the current target; iOS Keychain/build/device qualification remains N14. All real distribution/release gates stay closed.

Browser auth continues to use the current signed HttpOnly cookie, exact WEB_ORIGIN and CSRF checks. Native code must not obtain a browser cookie, disable Origin/CSRF or expose a reusable identity credential to JavaScript. The existing identity service accepts64hex credentials and owns account/session locks, privacy, revocation and erasure. Reuse that authority through an explicit native adapter, rather than creating another identity or room owner.

## Server boundary

Add a default-off native-auth flag and a separate server encryption key. A missing key with the flag enabled fails configuration validation. Native bootstrap/refresh/ticket/logout endpoints reject every Origin header and ambient Cookie. Native HTTP access uses an opaque `na1` bearer on an explicit adapter; it is not an identity cookie. The adapter rejects browser session/operator endpoints and installs the validated internal credential only for the current request. Existing route CSRF, permission, entitlement, moderation, idempotency and account-lock checks still run.

Use additive PostgreSQL tables for device families, short access grants, spent refresh hashes and one-use socket tickets. Preserve the original44SQL files. The underlying identity credential is encrypted at rest with AES-256-GCM, a fresh nonce and device/account/session-bound associated data; it never appears in native responses. Access, refresh and ticket values have disjoint prefixes and independent256bit random secrets; only hashes are stored. First bootstrap refresh reconstruction for an exact retry uses a domain-separated keyed derivation, never a stored plaintext secret. The old browser bootstrap/login request namespace is separate.

The native adapter passes a server-only authenticated grant reference to the identity owner, not an unscoped core credential. An optional identity-owned resolver rechecks the grant/family in the caller's transaction and limits context expiry to the grant. The second session check after an account-lock wait therefore also enforces native expiry/revocation. This reference is never accepted as an external bearer,returned to JavaScript or issued in a browser cookie. Browser64hex session resolution stays unchanged when the native port is absent.

An access grant lasts at most5minutes and cannot outlive its family/core session. A family cannot outlive the existing identity session. Refresh rotates atomically under the canonical account lock. A known spent refresh revokes the family and its core session; a random wrong token cannot revoke someone else's family. Concurrent refresh is deliberately fail closed: the Android bridge serializes it; uncertain/lost rotation acknowledgement can require sign-in again. No retry grace silently makes an old refresh reusable.

Socket tickets last at most30seconds and are atomically consumed in PostgreSQL. They bind the authenticated subject, device/core/access session, `native-socket-v1` audience, expiry and exact mandatory protocol offer/nonce. A ticket is sent only in Socket.IO auth, never a URL. The installed Android origin is exactly `https://localhost`; a native-origin connection cannot use a browser cookie/CSRF handshake. Browser-origin connections retain their old handshake. Every native command rechecks grant/family/core authorization; expiry, logout, device revoke and operator/account withdrawal close access. No native legacy-protocol downgrade is permitted.

Native device management returns only the requesting account's allowlisted device metadata. Account erasure cascades native rows; privacy export excludes hashes, ciphertext and credentials. Expired grants/tickets are pruned on issuance and families are bounded by the existing session lifecycle. Rollback disables the native transport and revokes native families without changing browser credentials or deleting historical SQL.

## Android boundary

Use a reviewed local Capacitor plugin, the Android Keystore AES-GCM provider and app-private encrypted storage. Do not use localStorage, preferences containing plaintext credentials, backup/export, logs, URLs or a plaintext fallback. Refresh state is persisted before publishing authentication success. Short access credentials stay inside the native adapter; JavaScript gets public identity/API results and a short one-use socket ticket. Public Me retains its existing in-memory CSRF field for shared-client compatibility; the adapter always supplies the current CSRF value itself. Materials/renderers do not receive bearer/refresh credentials.

The plugin has a fixed reviewed HTTPS API origin, rejects redirects/arbitrary hosts and denies raw native/session/operator requests through its general JavaScript fetch method. It supplies current native auth/CSRF itself. Network security checks remain enabled. A local TLS test CA, if needed, is scoped to a debug build and the exact local test domain; release builds must not trust it. Emulator Keystore custody is actual API coverage, not hardware-backed-key/physical-device proof.

The implemented custody port exposes operations rather than raw secure-store get/set. Android owns an AES256-GCM Keystore alias and AtomicFile ciphertext under noBackupFilesDir; origin/purpose are authenticated associated data and the device identifier is inside the encrypted payload. The plugin shares one process-wide serial executor with32queued-operation capacity,including Activity recreation. Access/CSRF remain in native memory; public Me retains its existing in-memory CSRF field. A read-back confirms persisted ciphertext before success. Corrupt/wrong-origin/unavailable storage fails closed. Immutable Java credential strings cannot be reliably zeroed; no claim of protection from a compromised OS/process is made.

Capacitor8 installs a process-global java.net.CookieHandler even when its cookie JavaScript API is disabled. Native HTTPS therefore uses a distinct pinned OkHttp4.12.0 client with CookieJar.NO_COOKIES,redirect/retry disabled and normal Android trust/hostname validation. It does not replace the global handler or modify browser cookies. The initial general request allowlist contains only GET/PATCH own profile/privacy; social endpoints require a later complete safety/business adapter. The release origin is empty; only debug builds accept the reviewed fixed-origin property. Normal HTML CSP remains self-only; the separate qualification mode adds only exact local test WSS. No arbitrary endpoint/CA input reaches the JavaScript bridge.

Migration45 adds four identity-owned tables with cascading bindings and no change to old SQL. Canonical runtime45 remains strict. The separately versioned `config/schema-compatibility-0044-native-expand.json` applies only to the pinned44-aware rollback runtime and explicitly includes45's checksum; it is not the current deployment default. Local source rollback must rebuild the genuine previous API/workspace packages,retain stable private keys,and demonstrate browser/native continuity on roll-forward. No down migration or public promotion is authorized by this policy.

Native sign-in does not enable a social room while safety/business adapters are missing. The existing logged-out preview remains the default. Generic secure-store and transport ports leave iOS implementation gated; no Android result certifies Keychain, WKWebView or an iPhone.

## Verification required before acceptance

Implement `test:native-auth` before invoking it. Exercise actual PostgreSQL HTTP and TCP Socket.IO: default-off behavior; wrong Origin/Cookie; cross-channel token rejection; unsupported/mismatched protocol; single-use and concurrent ticket consumption; expiration; refresh replay/race; current-user device revoke; operator/account withdrawal; erasure/export; sanitized logs; unchanged browser cookie/CSRF/legacy wire behavior. Run applicable security/integration/protocol/migration compatibility and build/type/boundary checks.

Build,inspect and install the actual DEBUG APK on the owned AVD. Verify Keystore encrypt/decrypt/restart custody, serialized refresh, fail-closed corrupt/unavailable storage, fixed HTTPS/redirect restrictions and logout/revoke without exposing credentials to the harness. Preserve failures and source/APK/policy hashes. Physical Android and N10-04 remain separate; no store/public activation follows from tests.

Primary references: [Android Keystore](https://developer.android.com/privacy-and-security/keystore), [Network Security Configuration](https://developer.android.com/privacy-and-security/security-config), [Socket.IO auth callback](https://socket.io/docs/v4/client-options/#auth), [RFC9700 refresh-token replay guidance](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14). The custom first-party protocol is not a claim of OAuth compliance or device attestation.
