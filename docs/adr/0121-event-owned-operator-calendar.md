# ADR0121: event-owned operator calendar

Date: 2026-11-06. Status: accepted for the N07-03 calendar slice; runtime controls remain unfinished.

Keep operator drafts outside the gameplay lifecycle. Saving a draft allocates no engine event, RSVP, reservation, room or consent. A draft names an existing active registered organizer; it never provisions a player, organizer grant, operator identity or world entitlement. Publication requires a current persisted organizer grant, current safety policy and an available public/listed event-capable world. The existing registry projection context enforces release/runtime usability and detects generation changes. No synthetic player session is issued to carry operator authority.

The singleton operator's fresh transaction boundary owns Origin/CSRF, authorization, optimistic revisions, request-key replay and fixed-reason immutable audit. The event owner creates published schedules and performs cancellation. Positive publication checks repeat after the audit write; expiry or world/grant loss rolls back all effects. Published event revision is separate from draft revision, so a player organizer's later edit causes an operator cancellation conflict until refreshed.

Extract one cancellation transaction helper for both existing player governance and the operator port. It keeps canonical account-before-event lock ordering, participant snapshot revalidation, reservations, invitations, Stage/Audience observation, notices and consent withdrawal intact. Cancellation remains possible with a disabled world. Notices and participation hints publish after COMMIT; unknown acknowledgement and exact replay reconcile only a canonically cancelled event's durable notices. Hints may repeat; event mutation, revision and audit do not.

Audit stores keyed organizer/title/draft references and bounded before/after operational metadata, with an HMAC chain. It retains no raw organizer UUID, title, profile, credential, participant list or request body. Operative draft configurations are included in the organizer's owner export and cascade on account erasure. Unpublished configurations expire after 30 days since save; published configurations retain until scheduled end plus 90 days; operator-cancelled configurations retain for 90 days. Existing event history/retention remains intact. The event maintenance path purges at most 100 expired draft configurations per pass. Immutable redacted audit remains retained like existing operator account receipts.

Migration 0042 is additive and requires strict 42 compatibility. Preserve the first 41 SQL files and historical evidence. No old-image compatibility widening, production down-migration or deployment is approved. Local synthetic fixtures and browser emulation do not establish real organizer provisioning, a public event, staffed operations or a physical-device gate.
