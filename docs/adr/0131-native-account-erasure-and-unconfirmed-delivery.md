# ADR0131 — Native account erasure and uncertain delivery

Accepted for the bounded N11-03 implementation,2026-11-07; not whole-task,owner,legal or store acceptance.

Reuse IdentityService.delete and its existing canonical account lock,domain erasure hooks,receipt transaction and post-commit session withdrawal. Add no database,table,authority or migration. Browser `/v1/me` deletion and the suspended-account privacy review/cookie workflow remain unchanged. Native uses a separate default-off `DELETE /v1/native/account`: opaque access,NI-bound CSRF,explicit true confirmation,request UUID and expected account UUID. The last field only rejects a stale view; it never selects an erasure target. Identity rechecks native scope after lock waits. No cookie is returned to native.

Android exposes a dedicated deleteAccount custody operation; general JavaScript HTTP remains GET/PATCH own profile/privacy only. The existing bounded process-wide queue serializes restore,account switch and deletion. Both Java and server compare the displayed expected account to the current authenticated account. The native adapter injects access and current CSRF; JavaScript receives only DELETED or UNCONFIRMED and local-cleared state. Destructive confirmation requires a real JSON boolean,never a coerced string. The UI requires an explicit checkbox and guards synchronous double submission,unmount and late results for another account.

Only strict200/schema1/deletedtrue confirms erasure. Lost ACK,server5xx,unparseable response or transport uncertainty clears local custody and returns UNCONFIRMED without automatic retry. A known4xx rejection is an error,not success. Authenticated response replay after cascading native rows is not promised: the existing identity receipt is not a new long-lived native authorization capability. No new table/token/grace window is introduced just to hide delivery uncertainty. Account deletion help stays accessible while signed out; logout,uninstall or401 alone never means account deletion completed.

The web resource `/account-deletion` links existing active-account controls and suspended registered-account privacy access. Shared text distinguishes live erasure from separate security/audit/backups and review access windows from an operational response SLA. Deployment retention,owner contact,store listing,Play account type/date,review coverage and owner disclosure approval remain unknown. The resource is local implementation,not a live public support URL. Mobile report/block/gameplay adapters and the remaining Play dossier still gate whole N11-03.

Verify wrong Origin/Cookie/CSRF/account,strict confirmation,concurrent confirmation,real lock expiry,domain rollback and actual socket withdrawal;actual Android form/Keystore/HTTPS/lost-ACK/account-switch/restart and browser resource checks. Preserve all45SQL,old ledgers/evidence and budgets. Source must remain fixed throughout full security/integration verification.
