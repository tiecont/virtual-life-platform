# ADR0071 — Local staging TLS and one explicit edge proxy

Status:M21-01 locally VERIFIED;actual outcomes are in m21-env-checks.json. This is a production-mode local staging equivalent. No actual external staging,public ingress,production deploy,domain purchase,public certificate issuance or release approval is granted.

The audit found working local dev/test PostgreSQL Compose and a signed Secure `__Host-city_session` production cookie,with exact Origin/CSRF controls. There was no application image,staging/prod environment matrix or Caddy config. Fastify did not trust forwarded IPs and Socket.IO counted the raw TCP peer;behind a reverse proxy this groups all clients into the edge IP's handshake budget. Blanket trust would let direct callers spoof rate limits. Cookie security must continue to derive from production configuration,not an arbitrary forwarded protocol header.

Keep one modular-monolith API,one Next process and PostgreSQL. Add one explicit optional IPv4 `TRUSTED_PROXY_IP` rather than trust-all/hop-count defaults. Fastify trusts only that peer. Socket.IO accepts exactly one valid forwarded IP only from that peer;unknown/malformed/list headers fall back to the TCP peer. IPv4-mapped TCP addresses normalize consistently. No proxy is trusted by default. The edge overwrites forwarded IP/protocol/host and strips `Forwarded`;application Origin/session checks remain authoritative. Proxy configuration grants no world,age,staff or participant permission.

Dev/test retain current scripts and isolated credentials. Staging/prod use NODE_ENV=production,HTTPS and independent DB volumes/secrets. Compose publishes only the TLS edge on loopback;API/web/DB have no host ports. A fixed private edge IP within a reviewed private subnet makes the trust boundary explicit. No cloud/CDN/multiple proxy chain is introduced. Owner approval and a separate ingress/release change are necessary for actual external staging/production. These templates must not be represented as deployed services.

One local application image builds the exact workspace/lockfile and serves API or web as a nonroot user. Build context excludes env/registry credentials/TLS keys/test artifacts/legacy references. Version-pinned bases and recorded image IDs establish tested bytes;this is not a signed supply-chain/security certification. Initial image keeps build/development dependencies;image minimization and vulnerability review remain before release. No secret is provided at build time.

Caddy consumes owner-provided certificate/key files outside build context,with admin endpoint off and no automatic external ACME request. The disposable local smoke generates a one-day local certificate and independently trusts it for Node TLS checks/Chromium's exact SPKI. It never installs a machine-wide CA. Explicit certificate mounts allow local verification without controlling a real domain. External certificate issuance,renewal/expiry alerts and real DNS/ingress remain operator work. The application is not exposed to public clients by this task.

No Caddy access log is enabled. Runtime error encoding removes request URI/headers/client-IP fields,including private dating source handles. The smoke deliberately stops the API and verifies an upstream502 log does not include a private path/cookie marker. Broader structured telemetry/tracing belongs to M21-03;backup/restore and rollout recovery remain M21-04/05.

The concrete smoke must validate actual Compose health/migration and unpublished upstream ports,trusted HTTPS certificate,real browser host-only Secure/HttpOnly/SameSite cookie,reload/rotation,Origin denial,authenticated TLS WebSocket,forwarded-IP spoof resistance and private error redaction. Disposable stack names/volumes/credentials are unique;cleanup may remove only that generated test project's volumes. It must never touch the retained city dev DB. Partial config validation alone is not runtime success.

Primary behavior references:[Caddy reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy),[runtime log options](https://caddyserver.com/docs/caddyfile/options#log),[log filters](https://caddyserver.com/docs/caddyfile/directives/log#filter). Actual local release/tool versions and retained preparation failures are recorded in the task evidence rather than inferred from the latest release label.
