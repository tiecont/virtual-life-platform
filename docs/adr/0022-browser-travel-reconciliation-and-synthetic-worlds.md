# ADR0022 - Browser travel confirmation and own-room reconciliation

Status: local M09-06 implementation, evidence tracked separately.

Add `/travel` as a native DOM confirmation/recovery surface linked from invitations and the local cafe. It shows only a server-confirmed current visit, identity/avatar choice and public available destination cards. Destination/world/capability is never placed in browser URL, storage or arbitrary redirects. Travel capabilities and pending keys remain in the owning component's memory, cleared on identity replacement. Refresh/reconnect reads the account's current room and uses ordinary guarded room.join to bind the new socket before reconciling an old committed request.

`GET /v1/me/room` is authenticated, bounded, strict-query, no-store and own-account only. It returns a filtered snapshot plus original world/scene versions, or null/lobby. Knowing a snapshot still does not redeem a different session's intent or authorize another account's command. This follows M06's one account/multi-session membership model. HTTP read does not create capacity or membership; the explicit socket rejoin remains subject to current admission/safety/versions.

UI disconnect clears live location and disables confirmation immediately. Old fetch/ACK callbacks are invalidated by operation/lifetime tickets; independent mutation tickets avoid stuck busy state when an error triggers reconciliation. A reconnect first confirms actual membership, then reads an outstanding intent. Historical COMMITTED is reconciled with the matching current target snapshot; null is never shown as successful travel. Uncertain creation/ACK preserves original keys for retry; completed/failed/expired/cancelled state cannot extend or reactivate. Manual refresh/retry/request closure and lobby return use trusted server state. Cross-tab source departure clears old authority before a tab explicitly refreshes or periodically reconciles. No peer activity is broadcast from this page.

Add three presence-only stateless sandbox adapters named Synthetic Deadline/Maid/Portal for W1 fault verification. They require explicit LOCAL_TRAVEL_FIXTURES=1 in development/test plus independent world flags. Configuration rejects that opt-in in production; sandbox registry guards independently reject production activation. They are DOM test destinations with no copied source, scene artwork, gameplay, staff, media or external resources. These are not playable/integrated legacy worlds; M15/M16 retain revision/redistribution gates.

Browser fault test passes real traffic through Playwright WebSocket routing, drops a real COMMITTED ACK, closes the transport, holds reconnect, checks actual PostgreSQL-backed current-room HTTP, then reconnects. A second authenticated tab observes source invalidation, manually reconciles to the same membership, and subsequent Portal travel retains exactly one account occupancy across all three worlds. No snapshot or receipt is fabricated. Desktop/mobile keyboard confirmation, no overflow and real screenshot/recovery artifacts are required evidence. Public activation, distributed recovery, production resources and legacy integration remain outside this verification.
