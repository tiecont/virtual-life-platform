# ADR0072 — Offline CI coverage and fail-closed quality gate

Status:M21-02 locally VERIFIED under [ADR0002](0002-local-foundation.md). Actual commands are in m21-ci-checks.json. The user explicitly requested offline execution:hosted CI/PR/branch protection remains NOT_RUN. No push,workflow dispatch,remote artifact upload or deployment occurred.

The current workflow combined root checks and every browser spec in15minutes. Actual local root checks alone take roughly9minutes;the19browser specs also require isolated API/DB lifetimes per spec/device. This creates a budget risk,not a measured hosted-runner timeout claim. Broad `artifacts/` archival could include unrelated local tooling or temporary infra env/certificate diagnostics. A failed upstream job can also skip downstream jobs,so the required aggregate must explicitly reject skipped/cancelled/missing results.

Keep a single required check named `quality`. A30minute core job runs the actual root lint/type/unit/integration/build command with isolated test PostgreSQL. It emits a validated browser plan. Five browser groups cover every existing spec exactly once;coverage rejects omissions,duplicates,unknown or traversing paths. Browser jobs depend on successful core,have30minute budgets,fail-fast false and max-parallel2. Each group builds locally and runs its specs sequentially through the existing per-device/spec disposable harness;no test quota is increased. These budgets/groupings are initial operational limits,not hosted timing guarantees.

The aggregate job uses `if: always()` with explicit core/browser dependencies and the exact tested `ciResult` program. Only two success results pass;failure,cancellation,skip,missing/malformed/extra job metadata fails. The browser matrix aggregate represents all groups. The invalid-plan fallback cannot produce success because the runner rejects unknown groups. The owner must later configure branch protection to require `quality`;a workflow file cannot establish that remote setting.

Retain read-only contents permission,pull_request rather than pull_request_target,no production secrets,checkout without persistent credentials and immutable reviewed action commits. Cancel superseded runs. Pin existing compatible v4 actions to the actual official tag commits resolved during this audit;these pins are not a transitive supply-chain certification. Fork jobs use only disposable synthetic credentials;there is no deploy/publish step.

Reports use `ci/group/spec/device` paths and per-group JSON summaries. Upload only `playwright-report/ci/<group>`, `test-results/ci/<group>` and `artifacts/ci/<group>` or the core log directory,with seven-day retention. Do not archive whole artifacts/env/tool/infra directories. Traces can contain synthetic test session traffic;they are private short-lived diagnostics,not real participant data or sanitized public reports. Browser fixtures/harness refuse nonlocal/nontest DBs and no production provider/credential is supplied. No actual GitHub artifact upload occurs in offline verification.

Acceptance requires actual actionlint/workflow/coverage/gate checks,a deliberately broken source rejected by the same root command,its removal and a positive root run,and actual browser group execution with distinct reports. Do not claim all five groups or a hosted PR ran merely because one group and a static matrix passed. Prior world acceptance remains separate evidence.

Actual evidence and tool checksum belong in m21-ci-checks.json.
