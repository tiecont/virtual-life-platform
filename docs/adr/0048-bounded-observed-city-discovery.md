# ADR0048 — Concentrate discovery using bounded owner observations

Status: local implementation; verification is recorded in m14-discovery-checks.json.

M14-05 adds authenticated, no-store `GET /v1/discovery`, with strict empty query input. It consumes the room owner's approved public catalog/anonymous allocation observation and the event owner's listed catalog. It owns no database tables and allocates no rooms. Dating, hidden, private, unavailable and safety-denied worlds are excluded. The client intersects suggestions with its current approved catalog and routes through explicit travel confirmation.

Rank occupied places first, then listed events starting within24hours or currently in progress; return at most3worlds. Choose a currently observed nonfull room when possible, without promising capacity. If all sources confirm no activity, suggest exactly one eligible real place using stable curated preference. Never manufacture a world, population or an array of empty rooms. Missing/truncated calendar data is explicit unknown and cannot justify an empty-city fallback. An unavailable room observation fails the read instead of becoming zero.

The room observation checks current identity, safety and catalog generations. Potentially slow catalog hooks execute outside the realtime owner queue; the actual allocation projection executes in one owner pass. The oldest observation time starts before catalog access, and snapshots expire after30seconds. These owner reads are not an atomic distributed snapshot. Counts are allocated places, including reconnect grace; transient travel holds and future admissions can change availability. No names, RSVP records, peer locations or bearer proofs enter the response.

The service reserves at most8global work slots before authentication and at most2per account, with30reads/account/minute and a separate HTTP IP budget. A stalled trusted owner retains its permit until actual work finishes. This bounds pending work; it does not certify production throughput or forcibly cancel uncooperative hooks. Shutdown rejects subsequent results. The browser uses an8second deadline, clears expired/hidden/offline/old-identity work and leaves the complete manual catalog available. Refresh rechecks eligibility rather than silently polling every world.

Tests use actual TCP/Socket.IO occupancy and durable event records, source outages, simultaneous pending requests and a held catalog hook while realtime snapshots continue. Browser event rows are isolated rendering fixtures, not operator provisioning or proof of organizer creation. No migration, real-world enablement, media approval or public release is included. Existing APIs and travel authorization remain unchanged.
