# ADR0038: Consented private event discovery

Status: Local implementation; evidence in m12-discovery-checks.json. Date:2026-11-03.

M12-05 reuses the platform InvitationService consent port: current friendship, bilateral block and recipient opt-in are authoritative. Event code does not read invitation preference or social tables. A transactional opt-out callback revokes event invitations and private-event participation; callback failure rolls back the preference change. Unfriend/block similarly cancels pending/accepted invitations. Re-enabling consent or friendship cannot reactivate the old grant.

An event organizer may invite a consenting friend before startsAt. Strict versioned create/respond schemas accept no caller role, phase, time or access authority. The pending offer lasts at most120seconds clipped at startsAt. Acceptance grants access until the event's fixed end, subject to current consent, world policy and safety on every command. Acceptance never creates an RSVP, table hold, seat or membership. Decline/cancel withdraws access and any private participation; own withdrawal remains possible during world closure. Separate sorted account locks and the event row serialize invitation mutation, contact withdrawal, allocation and cancellation.

Pending recipients may preview the offered title/world/schedule only in their own invitation inbox. Unaccepted users cannot directly read a private event. Terminal offers are omitted from the metadata inbox, so an expired/declined offer cannot disclose a later private schedule change. Own export preserves bounded receipt metadata without peer identifiers. Private sessions never enter global discovery, even for accepted participants. No roster, invitation token or contact identifier is broadcast. Postcommit event.invitation hints contain schemaVersion only; list reads always reauthorize.

GET events without a world filter collects eligible available public-world cards from the registry and returns at most50 upcoming listed events with truncation. Per-row authorization repeats current safety/block/policy checks. Hidden/restricted worlds and dating remain closed to this generic surface. Even a manually seeded adult event cannot be retrieved by an ineligible viewer. This is not an adult-verification approval or public launch. Disabled/stale-generation worlds cannot admit invitations or new allocations.

Mutation fingerprints and receipts make same-key retries durable; changed input conflicts and terminal retries do not renew consent. New invitation commands are bounded30/minute,20/hour for send,60/hour for respond, with50 active invites/event and50 pending/recipient. Creator permission and recipient safety are rechecked after awaited SQL. Acceptance crossing expiry while waiting for SQL ends EXPIRED in the transaction. Cancelled events withdraw invitations and include invite recipients in the existing deduplicated cancellation inbox. Account erasure and terminal-event90day retention cascade invitation/receipt records; own export bounds100, metadata inbox50 with truncation. No calendar/email is sent.

Migration0022 adds event-owned invitations and their mutation receipts, FKs and one active invitation per event/recipient. Existing public RSVP APIs remain compatible; EventCatalogQuery permits omission of worldSlug for global discovery. Rollback disables invitation routes/adapters and retains data. No legacy mutation, actual staff provisioning, event UI or real-world rollout occurred. Restricted-world event invitations require a separate reviewed design before expanding this public-world/private-session scope.
