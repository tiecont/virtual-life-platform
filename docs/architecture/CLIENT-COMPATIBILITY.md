# Client protocol and scene compatibility

`GET /v1/client-compatibility` returns only bounded public application/scene capability metadata. It does not report DB, hosts, secrets, account state or entitlements. The normal identity HTTP limiter and process drain guard apply. Discovery schemaVersion1 describes this metadata; application protocol1 and scene schema1 are independently selected. Socket.IO library/Engine.IO versions and the38-migration journal are separate concepts.

The current web adapter uses `resolveClientCompatibility`:404 alone means the route is absent and selects the legacy wire shape.503, malformed200, unsupported protocol/content schema or missing required capabilities do not downgrade. They show connection/reload/update outcomes without opening a gameplay socket. Successful discovery enables a fresh-nonce protocol offer. The gateway authenticates signed cookie/current session/CSRF before selecting support; incompatible offers receive explicit UPGRADE_REQUIRED. Native authentication remains a separate contract.

The opt-in server event is `session.compatibility`, echoing the nonce and selected protocol/scene schema/capabilities. The web client accepts it only for its current offer, waits before joining and ignores stale selections. It uses a bounded wait and clears pending waits on disconnect/disposal. Legacy clients omit the offer and receive no additional event or response fields. The raw prior web fixture is stored in `tests/fixtures/client-legacy-wire.json`; `node scripts/client-legacy-fixture.mjs` derives/checks it from immutable Git source. Full history/local access to that commit is required; the verifier does not fetch an unavailable object silently.

The entry button remains in the keyboard tab order during bootstrap, with `aria-disabled` and an explicit activation guard until identity/catalog/discovery/hash are ready. This preserves the skip-link path even on a delayed response; focus stays on the same control when it becomes available. Pending work cannot create a socket. Active command synchronization keeps its existing disabled controls.

New joins can include `sceneIdentity: {schemaVersion, sha256}`. The digest uses canonical JSON over a validated scene description: sorted object keys, meaningful array order and UTF8 SHA256. It detects changed geometry/labels even when someone mistakenly reuses a semantic version. It does not verify downloaded image/audio bytes or grant rights to them. Existing asset/provenance/release gates still apply. Legacy clients depend on immutable scene/world versions and omit the hash. Do not change content behind a supported version and claim that legacy clients gained hash protection.

RoomService validates an optional identity before allocation and rechecks current authorization/authority/generation/connection after the asynchronous hash. Mismatch uses the existing WORLD_VERSION_MISMATCH room error, so strict legacy ACK consumers retain their enum/schema. Authentication and snapshots/deltas/room-own envelopes remain unchanged. Scene-schema mismatches are not database migration mismatches.

`room-client-sequence-v1` lets the current panel use the existing bounded per-connection ordering adapter. A new connection starts a new stream. Sequence is not actor authority, transport delivery, an epoch, a room revision or a durable idempotency key. Snapshot repair and current-session checks remain mandatory. Full-snapshot deltas are advertised honestly; gap/epoch recovery clears unconfirmed state before mutation. Durable order/reward/travel receipts still own retry outcomes.

Run `pnpm test:protocol` for old and new contract/SDK/TCP/race/recovery cases. It now includes the compatibility fixtures and existing SDK gap/epoch tests. The browser study group includes current entry/hash/sequence, controlled absent-discovery fallback, unsupported update and unavailable metadata. Mobile Playwright is responsive emulation, not physical Android/iOS evidence. [Actual task results](N05-06-CLIENT-COMPATIBILITY.json) record completed/failed/interrupted commands and limits. The first released N−1 mobile binary remains NOT_APPLICABLE while no mobile clients are distributed; do not invent a successful old-binary run.

See [ADR0113](../adr/0113-additive-client-and-content-compatibility.md). No protocol negotiation result authorizes a public/store release, server promotion, extra room owner or restricted world.
