# Private connections and return conversations

M20-05 adds a closed synthetic-test-only continuation to the native private DateRoom. See [ADR0070](../adr/0070-private-mutual-continuations-and-consent-scoped-return-queues.md) and [actual evidence](../agent/evidence/m20-continuation-checks.json). Normal development/production has no positive eligibility provider. All real rollout and eight approval gates remain closed;this is not a controlled pilot or effective real-world age verification.

After an actual started conversation ends,each participant may explicitly keep one private connection choice. A unilateral choice sends no notification and leaves the other participant's NONE observation—including own revisions,times and grants—identical. Only two current consenting choices expose MUTUAL and the neutral private alias. One choice occupies only its owner's slot;it cannot reserve the peer. Global active choice membership is bounded at100. There is no general friendship,DM,contact exchange,scoreboard or reward.

The first choice expires at the original date creation plus24hours. Mutual consent lasts at most720hours from the second choice. A kept connection survives ordinary24hour date-history cleanup because its minimal consent header has no cascading date FK. It stores pair/source/profile snapshots,choice versions and timestamps,not message content or copied public identity. Source handles remain in component memory,not URL or browser storage. List observations contain at most20 own source handles and expire within5seconds.

Meeting again requires both people to independently join the same source-scoped120second queue,accept a new45second proposal,and separately enter the new timed DateRoom. This reuses the existing one-allocation-per-account matcher and original-session/proof/safety guards. General queues and other connection sources cannot pair. A short account/session/profile/source/negative-consent-bound return grant authorizes one command,not perpetual messaging. Canonical same-key retries read current state without renewing a queue;revoke defeats old retries.

Positive work takes the matcher SQL mutex,captures all affected accounts,locks them in sorted order,and locks the sorted union of related active continuation headers before any profile callback or proposal/date lock. Negative owner callbacks acquire no new peer account/global matcher/Room lock. They close sorted source headers before proposals/dates and members. App profile/block/deletion callbacks invalidate continuations before matching. Ordinary Date Leave stops its round while preserving the kept choice. Profile edits/withdrawal/expiry,block and erasure invalidate kept consent even when the original enrollment is gone.

Authenticated Origin/CSRF/idempotency-protected withdrawal works without a positive proof,key,feature flag or reporting service and has a separate HTTP quota lane. It records a historical request;an old receipt cannot undo later cross-tab choices. Negative effects still commit after200 daily negative receipts while additional receipt storage is capped. Native controls discard held positive replies after withdrawal,clear old observations at5seconds,and remain available on `/private/withdraw` after positive deep links deny access.

The service limits new likes to12/hour,active recovery to20headers/batch,and cleanup to100rows/table/batch. Positive receipts expire after24hours,negative receipts/consent tombstones after2160hours. The shared3second scheduler/shutdown wait owns recovery. Export contains at most100 own command metadata records plus a truncation flag,without peer/source IDs;account deletion invalidates source work before FK cascades. These fixed draft retention defaults are checked against policy;human privacy/retention review and backup-deletion decisions remain external gates. Bounded fixture tests do not certify sustained load or all storage caps.

Migration0036 is additive to0035;old migration checksums are unchanged. Deploying this build requires migration before readiness. Runtime rollback should keep positive flags OFF and retain independent negative controls;there is no destructive down migration. See evidence for actual retained-local application status.

Dedicated opaque private block management,independent privacy assessment,real eligibility verification,staffed coverage and operator/legal approval are still required before real operation.
