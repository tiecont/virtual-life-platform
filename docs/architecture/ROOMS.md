# Authoritative rooms v1

Implementation: apps/platform-api/src/rooms/service.ts, one process/owner, per-instance epoch UUID, bounded room/membership/receipt maps and serialized command queue. Shipped sandbox capacity:8. Task evidence for M06 is in docs/agent; this does not register actual worlds, render a browser scene or authorize release.

Socket events reuse the origin/CSRF/cookie identity gateway. room.join, room.leave and room.snapshot require strict schemas/ACKs and real PostgreSQL session checks for every command. No accountId/role authority accepted. Max pending per socket:8; existing transport/session command budgets apply. Unknown events disconnect. No arbitrary world command passthrough.

room.join contains schemaVersion:1, requestId, worldSlug, exact worldVersion/sceneVersion, optional roomId. Without target prefer occupied rooms with free capacity; create at most 32/world,128/process. Serialized allocation adds provisional membership before SDK onJoin, authorized by this owner. Failure/disconnect/world generation change rolls back. Full specified target returns ROOM_FULL. A different current room returns ALREADY_IN_ROOM; safe handoff is M09.

One account owns one room membership across authenticated tabs/sessions. Duplicate join receipt returns current snapshot only while that membership exists; never resurrects a left membership. Changed input/session key reuse returns IDEMPOTENCY_CONFLICT. Process-local receipts:5-minute TTL,10,000 cap. Restart loses runtime state/receipts; fresh epoch and explicit rejoin required. No persistent domain transaction guarantee is claimed.

room.snapshot/room.leave require requestId, epoch, roomId,membershipId matched to connection/account/session; foreign IDs/old epochs denied. Snapshot has own accountId/membership/seat, room/world IDs, capacity, aggregate occupancy, roomVersion and anonymous seat availability; no peer profiles. GET /v1/worlds/:slug/rooms applies session/world access, no-store/rate limits and aggregate-only output. Disabled world:WORLD_UNAVAILABLE; unknown/unauthorized:NOT_FOUND.

Leave removes all tabs' membership and emits room.ended. Final disconnect holds membership/capacity/seat for 15 seconds; a newly authenticated connection can join again with a new requestId and retain its membership/seat before expiry. Expired grace is swept before admission/claims/snapshots, so a stale timer cannot reserve a seat indefinitely. Logout/rotation/deletion revocation clears that session's connections/ownership immediately; surviving sessions retain the shared membership, with a bounded grace if none remain connected. World disable/offline immediately invalidates admission generations, then removes rooms and emits room.ended. Empty rooms evict after 60 seconds on command/maintenance sweep (main maintenance every 5 minutes). Maps bounded, no simulated players. Shutdown closes transports/discards state. No DB migration.

## Seats (M06-02)

WorldDefinition adds optional seatIds (default empty for existing presence-only modules). Unique IDs must match the seating capability and fit capacity. This is a local prerelease contract evolution; no deployed legacy client is silently upgraded. Coordinates/rendering remain M07. Sandbox declares 8 seats. seat.claim/seat.release extend the own-membership envelope with seatId; ACK is the latest authoritative snapshot. Claims serialize with allocation/leave, require live session/membership/world access, enforce one seat/account and one owner/seat. Occupied/held seat -> SEAT_TAKEN; another seat already owned -> ALREADY_SEATED; foreign release -> FORBIDDEN; unknown seat -> NOT_FOUND. Free-seat release is idempotent.

Receipts are operation/input/session scoped. Replaying an old claim after release returns current state and never resurrects ownership; key reuse for another seat/operation conflicts. Snapshot seats expose seatId,state (available/occupied/held),mine only, never another owner's account. Grace holds seats/capacity; explicit leave/expiry/revocation/world disable frees them. Snapshot validator rejects overcapacity, duplicate seat IDs and inconsistent self ownership. 100-account controlled-connection fixtures verify claim races against real sessions/service; actual Socket.IO tests verify ownership/grace/replay/logout. This is not a network performance benchmark.

## Realtime guards (M06-03)

M03 handshake checks stay active: exact Origin, signed city cookie, CSRF/schema, DB session TTL/revocation, max4 sockets/session, bounded transport buffers and connection rates. Room handlers allow only registered events with strict per-action envelopes and ACKs. Unknown actions/role/account fields fail. Every accepted command runs the session gateway guard and room service guard; budgets are shared across event names (60/session/minute) and max8 pending/socket. A slow-hook network test sends10 pending joins:8 successful idempotent membership joins,2 RATE_LIMITED, occupancy1. Runtime replay receipts never reapply old mutations; altered scope/input conflicts.

The gateway's trusted session-ended callback removes corresponding room sessions on idle expiry or next-command discovery of revocation. This is distinct from ordinary network loss, which keeps bounded grace. HTTP revocation also notifies the room service directly. No expired session can prolong its seat by repeatedly issuing invalid commands. These local tests do not replace a production edge/TLS/security review.

## Privacy-safe peers and client sync (M06-04)

RoomSnapshot now contains the viewer's own account/profile plus peer profiles that pass platform presence policy for the current world. PostgreSQL social relationships are authoritative; bilateral blocks override friendship and public presence. Hidden presence, unknown worlds and dating never enter a room projection. Seat state is anonymous (`mine` is viewer-relative). Profile, privacy and social block changes refresh affected rooms and emit viewer-specific `room.delta` events.

Room versions increase for membership, seat, reconnect and privacy/profile projection changes. Delta envelopes carry `fromVersion` and complete filtered state. The SDK reducer requires matching epoch/room/world context, applies contiguous versions, ignores duplicates/old states and reports gaps for snapshot resync. The server recomputes each viewer projection, so clients cannot widen visibility by editing a delta.

M06-04 evidence covers public/hidden presence, bilateral block projection, live viewer-safe delta, duplicate/out-of-order/gap reducer behavior and previous room/seat guards. This is not a rendered scene or high-fanout performance result. Projection failure must fail closed; operational metrics and client retry UX remain M06-05/M06-06 work.

## Recovery (M06-05)

Fastify preClose removes room state and emits room.ended(server-stopping) before gateway shutdown. SIGKILL has no final event; clients treat transport loss as unconfirmed until a new snapshot. RoomRecovery exposes idle/syncing/active/reconnecting/interrupted plus sanitized reason. Offline/gap/ended state returns no live snapshot; cached peers and seats cannot appear authoritative. Sync tickets reject late ACKs after disconnect/ended/new sync. A fresh snapshot after epoch/membership change marks membership-reset. Only active matching context/membership/account deltas apply. A browser view must consume this state in M07; no rendered recovery UI is claimed yet.

Actual child-process restart on the same port and DB verifies stale membership rejection, new epoch/membership, occupancy1 and no seat resurrection. Grace reconnect/multi-tab preserve one account membership and seat; seat/detach/reconnect/expiry deltas are contiguous. Restart is interruption, not durable room recovery. Critical orders/focus will need their domain reconciliation separately.

## Metrics and pressure (M06-06)

RoomMetrics uses fixed command/error labels and12 fixed non-cumulative latency buckets(last upperMs:null means infinity). Counters/max/total only,no per-user/room/world labels or raw samples. createApp.diagnostics() returns operator-only aggregate socket/transport/room/membership/seat/grace/receipt/queue totals; no HTTP endpoint exposes it. M21 may export protected metrics later. Test-runtime IPC provides CPU/RSS/diagnostics; production has no IPC listener.

External pending cap256 and8/socket/session60/minute remain active. Maintenance/refresh and trusted cleanup coalesce: keys restricted to existing room world/session/connection state; unknown disconnect/refresh/session identifiers do not allocate queue keys. Control jobs reserve cleanup capacity beyond admission cap; this is not a fixed256 cap on all cleanup. Deltas use volatile transport; non-writable peers lose replaceable updates,32 consecutive drops disconnect. Consumers must snapshot on gaps/reconnect and periodically reconcile even when no next delta arrives; M07 must implement this browser behavior. Reliable command budgets remain bounded by incoming rate/concurrency limits.

See ROOM-BENCHMARK.md and m06-network-baseline.json for the actual 24-socket baseline and limits. Controlled non-writable fixture verifies dropping, not WAN slow-reader capacity. No scene/chat/movement/travel success claimed. Disconnected world-hook cleanup and lifecycle deadlines must be addressed before enabling a resource-owning world; the synthetic sandbox holds no per-player resources. Lifecycle hooks are trusted application code, not arbitrary uploaded modules.

## Exclusive Owner (M06-07)

RoomAuthority acquires one PostgreSQL session advisory lock per current DB schema on a dedicated connection, lazily on first room operation. No second process can admit rooms with that key. Lock contention returns WORLD_UNAVAILABLE and makes readiness 503 after an attempted room operation. An idle process without room work does not acquire a lock merely for health checks. Identity/social can run independently, but multiple room replicas are unsupported.

Every external room command checks authority before/after execution; viewer delta publication and SDK membership grants also verify it. Heartbeat checks idle authority every second. Query/acquisition deadlines are one/two seconds. On connection loss, timeout or missing lock, the process permanently loses room authority: discard ephemeral state, send authority-lost interruption to current room connections, disconnect them and deny further commands until process restart. No automatic reacquisition. Graceful close destroys the dedicated connection after room interruption cleanup.

This is not a durable monotonic fencing token or distributed failover lease. See ADR 0009 for direct/session-affine PostgreSQL requirements, stale delivery limits and rollback; FUTURE-OWNERSHIP.md still gates horizontal scaling. Real tests pause an owner with SIGSTOP, terminate its isolated test DB lock backend, admit a competing process, resume the old one and verify denial. The test does not simulate multiple database primaries or certify a WAN partition protocol.
