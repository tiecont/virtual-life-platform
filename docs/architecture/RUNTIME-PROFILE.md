# Runtime phases and executable local profile

`RoomMetrics` retains its previous total gateway counters and adds bounded owner-work observations for the six existing room commands. The composition root shares that instance between RoomService, gateway diagnostics and the private operations endpoint. Labels are command/outcome/phase from fixed sets; no SQL, request payload, account, room or world IDs are metric labels. Internal/engine/safety work remains outside the new room-command context. Event-loop monitoring is process-wide, not a dating activity trace or browser frame-time measurement.

| Phase | Measured value per command | Scope |
|---|---|---|
| queue_wait | Monotonic wall interval from enqueue to owner callback | Includes contention from every preceding owner operation |
| execution | Owner callback, guards and work after dequeue | Includes awaited DB/projection and selected synchronous work |
| projection | Outer projection-batch and response snapshot wall spans | Nested snapshot spans within a batch are suppressed; all private workers still drain before queue release |
| fanout | Synchronous listener/Socket.IO dispatch wall spans | Includes serialization/enqueue work; does not measure client delivery or pure network delay |
| path_compute | Selected synchronous trusted pathfinding calls | Not all CPU used by a command |
| db_pool_wait | Sum of initiated pg acquisition wall spans | Includes checkout queue/new-connection work; concurrent spans can overlap |
| db_query | Sum of initiated pg query wall spans | Includes driver/transport/server wait; parallel queries can exceed execution wall time |

The histogram sample count is a command count. DB values are per-command span sums, not individual-query latency distributions. These nested/parallel observations must not be added into a purported CPU decomposition. Initial gateway authentication and pre-service validation/rate rejects remain in the existing gateway total and client round-trip metrics. Coalesced owner checks or background calls initiated outside the room command are unattributed. Missing DB attachment is explicitly not_attached; unsupported calls are counted rather than presented as complete zero-cost SQL coverage.

The pg adapter observes current Promise/callback paths, including Pool.query's internal callback checkout. It preserves result/error objects, release ownership and double-release behavior, restores wrappers and reference-counts shared pools. Unsupported Submittable or unstable custom methods are left intact. Command lifetimes prevent late/background observations from changing completed samples. Three actual PostgreSQL regressions cover waiting, callbacks/Promises/errors, shared attachment, unsupported query forms, observer failure and cross-context handoff attribution. Observers do not retain query text/parameters/rows/credentials.

Private JSON and Prometheus output expose the phase histograms; the legacy HTTP/room counters remain. The event-loop histogram uses Node monitorEventLoopDelay at20ms resolution with sample count, p50/p95/p99/max. Empty/warming/stopped observations use null, not a false zero. Application close disables the histogram/async context and restores the pool adapter. Existing authentication/Origin and operator-only endpoint gates remain unchanged.

Run `pnpm profile:runtime` after its implemented script is present. It builds existing packages, starts the guarded disposable DB and a separate test API child, creates synthetic public-profile actors, then runs room join/snapshot, two real server-path movement waves, seat/duplicate/stale-request cases, two reconnects and leave. Default12 actors; `ROOM_PROFILE_ACTORS` accepts8..24 only. Real loopback guest addresses preserve IP budgets; handshake/session/pending/room limits are unchanged. The fixture has a60second cancellation deadline and a bounded owned-child shutdown fallback. Outputs use the existing unique private evidence helper.

The report records source/diff identity, runtime/hardware/cgroup/PostgreSQL environment, accepted/rejected/all-attempt round trips, process CPU/memory/event-loop, owner phase histograms, observed Socket.IO text sizes and API-facing TCP totals. Socket.IO text sizes exclude Engine.IO/WebSocket/TLS framing; the separate TCP counter includes application HTTP/socket framing but excludes DB traffic. Server/generator/DB share the host; only API process CPU is reported as server CPU. A local short fixture is not a sustainable-CCU, physical-device, WAN/TLS or full gameplay-mix qualification.
