# Current authority invariants and protocol adapters

N05-01 builds on the current modular monolith. The table maps implemented enforcement to executable regression coverage; plans for distributed ownership, native auth and admission remain separate. These tests use isolated synthetic accounts/data, actual local PostgreSQL and HTTP/Socket.IO, and labelled controlled faults. They do not establish a production CCU or real-world safety approval.

Source paths in the table are under `apps/platform-api/src/`; integration tests are under `tests/integration/`. Existing safety/privacy checks remain authoritative on retries. An ephemeral room receipt is not a durable business receipt and never grants membership after the owner/membership ends.

The shared envelope remains `{schemaVersion:1, requestId:<UUID>}`. Existing event names and flat room fields remain the current adapters. `room.join` retains its exact version/asset negotiation; owned room mutations can additionally carry clientSeq. Actor/role/age, authority paths and timestamps are never client grants. Chat and durable HTTP mutation bodies keep their existing strict schemas and idempotency headers.

clientSeq is a safe integer from0 to2147483647. New seat/movement/leave requests at or below that connection's accepted watermark fail with IDEMPOTENCY_CONFLICT. Reusing a requestId with different action/input still conflicts independently. A known matching receipt returns current viewer-safe state without applying the old action or moving the watermark backwards. Failed pre-effect validation does not consume ordering; an effect followed by projection failure does. Snapshot reads do not advance ordering. On sequence exhaustion reconnect/resync into a new stream; never wrap the existing stream to0.

The watermark belongs to the live connection/member and is cleaned up on detach/revoke/removal. Repeated join on the same connection preserves it. A compensated travel keeps the original member/watermarks; a committed new membership starts fresh. Legacy commands without the field retain their previous behavior, so optional ordering must not be treated as a security barrier. No product web/mobile client starts sending it in this task.

These counters have different meanings: schemaVersion is the existing wire shape; clientSeq orders capable-client room mutations; roomVersion/fromVersion order authoritative room state; epoch identifies the current in-memory owner; durable idempotency keys/expected versions protect business transactions; SQL migration count and metadata version describe database compatibility. Current room.delta still carries a full viewer snapshot. There is no exactly-once transport guarantee or distributed fencing lease.
