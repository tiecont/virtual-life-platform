# Confidential local reports

M08-03 adds authenticated report intake and a room report/block dialog. It does not create moderators or promise a staffed response. A separate `SAFETY_EVIDENCE_KEY` (32 random bytes encoded as 64 hex characters) and stable `SAFETY_EVIDENCE_KEY_ID` enable confidential reports only in development/test. Without a key, the status endpoint truthfully says unavailable and report/case operations deny. Production always denies. Normal chat and real world rollout flags remain OFF.

## Intake and evidence

`POST /v1/reports` requires a signed session, Origin/CSRF, UUID idempotency header and strict versioned input. A room report derives the world/subject from current authoritative epoch, membership, active session and visible participant projection. It rejects self-report, fabricated rooms/peers, unknown contexts and invisible targets. A room report captures a bounded reporter allegation and minimal context, not proof of misconduct. No client-supplied message body, severity, role or recipient is accepted.

Message reports accept at most five distinct server message references from one sender/room. Only recipients to whom the live server attempted an approved delivery may use them, including after block/leave. This is not proof that a network recipient read the message. When the separate report key is configured, an encrypted volatile cache retains at most 1,000 messages, 100 recipient account IDs/message and five minutes of reference eligibility. A reference expires or can be evicted earlier; restart loses it. No ordinary chat history is written to PostgreSQL. Maintenance clears expired memory entries; access denies immediately at expiry. Room reporting remains possible without chat being enabled.

The service commits one case, AES-256-GCM encrypted evidence and append-only audit in one transaction. AAD binds ciphertext to schema/key identity and the case ID; substituted ciphertext, wrong keys and corrupt tags fail safely. Notes are capped at 1,000 characters and evidence at 32 KiB. A persistent five-reports/account/day budget survives tab/session changes and process restart. Concurrent matching retries return one random private receipt, without duplicate cases/audit; changed payload conflicts. Report counts never automatically sanction someone. Receipt reads are reporter-only and reveal no moderator/case/evidence details to the target. Reports produce no room/socket notification. Request logs redact safety object IDs and omit bodies.

## Staff access

`GET /v1/moderation/cases` returns bounded summaries (25/page, opaque UUID cursor): moderators see assigned cases within their world grant; safety admins may triage summaries in their scoped worlds. Reporter/subject conflicts are excluded. Registered identity plus an unexpired database grant is required on every operation; a profile, world costume or client role is never authority. There is no grant/self-promotion HTTP endpoint. Local tests provision synthetic grants directly in disposable databases; no real staff is provisioned here.

`POST /v1/moderation/cases/:id/assignment` requires a scoped safety admin, valid scoped registered assignee and an allowlisted purpose. Reporter/subject cannot assign or review their own case. Staff-abuse cases require an independent safety admin. Assignment receipts are durable/idempotent; retry cannot undo a later reassignment. `GET /v1/moderation/cases/:id` requires current assignment and current scope even for an admin. It returns allegation evidence, never an explicit reporter ID, and appends an audited view in the same transaction. Changing/revoking/expiring grants removes access on the next operation. A note voluntarily identifying its author remains private evidence; no anonymity guarantee against inference is claimed.

## Storage and deletion

Migration `0005_reports.sql` is additive and city-owned. Tables: staff grants, cases, encrypted evidence, assignment receipts and audit events. PostgreSQL triggers reject audit UPDATE/DELETE/TRUNCATE; no public audit mutation/read route exists. Audit contains fixed actions/purposes, case IDs and HMAC actor digests, never notes/message bodies/reporter IDs. This is application-level append-only enforcement, not protection against a database owner disabling triggers or changing code. Staff provisioning/auth hardening and independent operational audits remain release gates.

Evidence is unreadable after the draft policy TTL (30 days by default). Internal maintenance deletes at most 100 expired evidence rows/transaction, records purge events and coalesces concurrent runs. The main process invokes maintenance every five minutes; backlogs can take additional runs. Expiry/read denial does not depend on the job executing. Case/audit/assignment metadata retention and approved legal holds still need M08-06 and owner review; full retention compliance is not claimed. No hold or indefinite evidence exemption is implemented.

Explicit account deletion and automatic expired-guest cleanup invoke the safety deletion hook in the identity transaction before FK unlinking. Associated evidence is erased, cache references forgotten, reporter/subject links become NULL and non-body audit survives. This local conservative erasure policy avoids silently retaining identifiable ciphertext. It is not an approved investigation/legal-hold policy; public rollout remains blocked until the privacy owner reviews that tradeoff. Own export includes private submitted receipts (100 max with explicit truncation), no reports against the viewer and no confidential evidence; full reviewed safety DSR handling remains gated.

Keep the evidence key separate from session signing, stable across restarts, ignored by git and outside logs. Wrong/missing keys must not be replaced silently: existing evidence becomes unavailable, not plaintext. This slice supports one configured key identity, not automatic rotation, KMS, multi-key decrypt or a backup/restore certification. No destructive down migration is shipped. Local rollback disables reports by removing its key, closes the new UI path and retains additive tables; do not delete preserved audit/cases during rollback.

For a local preview, `pnpm setup:safety` creates ignored `.env.safety` with a generated key and mode0600, refusing to overwrite an existing key. `pnpm dev` reads that optional file after `.env`. This opts into local confidential reporting, not chat/world/public activation. Store it securely and keep it for existing evidence; do not rerun setup as a key-recovery mechanism. Tests use separate explicit disposable fixture keys. No real privileged identity is provisioned by setup.

The report dialog has explicit labels, native modal focus containment, keyboard opening/closing, receipt focus and focus fallback after blocking removes the opener. It retains a draft through a temporary room resync, clears on identity/membership loss, cancels requests on teardown and uses an eight-second UI deadline. An interrupted successful HTTP response is shown as unconfirmed; matching retry uses the same idempotency key and retrieves the original receipt. No note is stored in browser persistence.

Actual commands, initial failures/corrections and screenshots are recorded in the M08-03 evidence/checkpoints. Sanctions, appeal lifecycle and moderator UI/emergency controls remain M08-04/05; broad false-positive, retention and operations review remains M08-06. W1 remains incomplete.
