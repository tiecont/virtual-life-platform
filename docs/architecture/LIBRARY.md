# Eternal Library

The original Library module in packages/library-world defines eight desks and one shared quiet layout. Reading corner is for individual reading;Study alcove provides quiet company at shared desks. These labels identify areas,not private/isolation guarantees. No book files,audio,task notes or automatic social progress are distributed. Server room capacity/seat authority and the current session remain authoritative.

`/worlds/library` renders original deterministic shelves,decorative book spines,tables,plants and the existing original avatars. Native desk and movement buttons provide all essential actions when the canvas fails. The same WorldRoomPanel/RoomSafety components power the SDK sandbox;there is no second realtime or seat implementation. Entry requires a current approved catalog/version and explicit action. Opening the page does not allocate a place. The shared travel desk remains the route for cross-world admission.

## Local verification setup

Set `LOCAL_LIBRARY_WORLD=1` only in a development/test API environment and set `library:true` in that environment's trusted WORLD_FLAGS_FILE. These are separate gates;missing either does not admit a Library visit. Production rejects LOCAL_LIBRARY_WORLD=1. Default flags and publicRelease remain OFF. Stop/reload/disable using the existing registry/flag lifecycle;disabling closes active Library memberships. No migration or separate account/focus database exists.

`node scripts/run-browser-tests.mjs tests/e2e/library.spec.ts` selects the isolated Library browser flag fixture. Default full runs also isolate that spec/profile;other specs retain their original fixture. This is local implementation testing,not public enablement or staffed operations. Original art sources/provenance are at `/assets/library/provenance.json`;releaseApproved remains false.

## Slice scope

M17-01 provides scene,desk areas,access and native controls. M17-02 enables shared focus in world version1.1.0,using the unchanged scene1.0.0. It reuses the existing private timer/history and account-wide one-active rule. Start requires the server's current Library seat;bounded pause/resume is explicitly allowed here. Leaving or losing the room does not cancel or reset the durable timer. Restarted/finished history retains its original Library/room/desk scope. A public profile does not make the timer public;no task notes or productivity are broadcast.

No new timer database or per-second writes are introduced. Interrupted browser starts retain their exact mutation key;user retry observes the committed timer. Pause and completion use server time,not the browser clock. Integration tests advance only an injected trusted server clock;browser tests verify the actual response-loss/pause/resume/leave/cancel flow. See ADR0052/m17-focus-checks.json for actual outcomes and limits.

M17-03 enables listed silent study schedules in world1.2.0 with policy1.0.0/max8RSVPs. WorldEvents reuses M12catalog/RSVP/withdraw,showing at most five listed sessions,owner timezone labels and only the viewer's RSVP. Server scheduling authority remains default-deny;the Library UI grants no organizer role. Chat,canned messages,emotes and audio remain unavailable even if the shared chat runtime is enabled. Decorative avatar movement is not a chat/emote channel.

An RSVP does not reserve a room or desk. Capacity/consent/current phase remain server-authoritative;entry is a separate explicit travel review. Schedules clear after30seconds,visibility/offline loss,failed reads or identity changes. An outage never appears as an empty schedule. Unknown mutation replies preserve their exact key for explicit retry. Current-state reads and last-observed RSVP labels are not a push guarantee. Public listed catalog never includes private study sessions;group invitation flows are a later slice.

M17-03tests distinguish actual owner API scheduling with synthetic trusted organizer authority from browser SQL rendering fixtures;neither provisions real operators. See ADR0053/m17-events-checks.json for commands,actual results and limits.

M17-04adds opt-in phase counts for confirmed study participants in the same actual Library visit. The viewer must opt in too. Only connected,consenting,safety-eligible participants whose profile is visible to that viewer contribute. Names,timer IDs,durations and task text are absent from the result. Counts can still allow inference about a consenting visible person in a small group;the UI states the intended audience. A five-second snapshot is an observation,not a live productivity feed.

Sharing defaults OFF and is kept in bounded process memory for one session/room epoch/membership/event. Stop works outside the room;old retries cannot reactivate a stopped choice. Restart,departure,identity/privacy/contact changes and RSVP withdrawal revoke it. Temporary disconnect suppresses contribution;valid same-visit reconnect within the room grace window may restore the prior choice. No new SQL table,analytics preference or persistent privacy grant is created. Export reports only the caller's own ephemeral choice;erasure and session revocation clear it. Owner failure or stale work yields unavailable rather than fabricated counts.

An active Library visit can offer its exact public room to a friend who allows invitations. The invitation inbox first accepts the offer,then links to explicit room review and travel confirmation. Neither sending nor accepting admits a room or creates a study RSVP. The server rechecks room/world scope,current access,version and capacity. Opening the Library scene after travel reattaches the same membership. An unavailable/full room has no automatic fallback. See ADR0054/m17-sharing-checks.json for actual verification and compatibility notes.

M17-05 now verifies actual Deadline integration after M15:18Library API and20desktop/mobile browser cases pass. A controlled trusted serverclock completes one900second Library timer under six concurrent finishes;actual Socket travel to Deadline preserves private Library history/summary and does not duplicate it into Deadline history. The browser starts at City Portal,reconnects the real Library transport with the same seat/timer,then opens actual Deadline and cancels the continuing Library-origin timer through native controls before confirmed City return. Browser cancellation is explicitly separate from server-clock completion;no15minute wall-time claim is made. Quiet report/block,RSVP/sharing and mobile remain functional. See ADR0096/m17-actual-journey-checks.json and LIBRARY-VERIFICATION.md. All five local tasks are verified;public/operator gates and cross-module release acceptance remain separate.
