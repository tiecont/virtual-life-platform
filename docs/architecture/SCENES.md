# Scene contract and local test cafe

M07-01 defines a versioned orthogonal tile manifest in `packages/contracts/src/scene.ts`. Tiles use integer coordinates from the top left; pixel center is `(tile + 0.5) * tileSize`. Bounds, duplicate collision IDs, duplicate seat IDs/tiles and blocked/outside spawn/seats fail validation. The synthetic SDK cafe is 20 by 14 tiles at 48 pixels per tile with eight server seat IDs. Collision geometry is declarative; authoritative movement is M07-04, not implied by this renderer.

`packages/pixi-scene` uses the cached pinned Pixi 8.22.0. The cafe draws deterministic original geometry and now loads the original starter avatar atlas. No legacy source/art was copied. The original M07-01 fixture/provenance is retained under `assets/sandbox`; current starter source/dimensions/rights are under `assets/avatars/provenance.json`. Release approval is false. M07-03 provides the starter actions/outfits described below.

`/worlds/sdk-sandbox` provides authenticated room entry/exit and seat controls via the M06 Socket.IO contracts and RoomRecovery adapter. Profiles are viewer-filtered on the server; no synthetic peers are added. Self is represented even with hidden presence. Occupied anonymous seats never disclose a hidden occupant. Network loss clears confirmed scene state. A 15-second snapshot refresh reconciles a final dropped delta with no subsequent event. The canvas has an equivalent labeled seat list and visit/participant status outside it. Comprehensive accessibility and performance gates remain open.

The normal registry remains disabled. `tests/fixtures/world-flags.json` opts only synthetic sandbox into development/test; production remains empty. To preview locally, explicitly set `WORLD_FLAGS_FILE` to its absolute path when running `pnpm dev`, after the normal local database setup/migrations. This does not activate a real world or authorize release.

M07-01 verification: `m07-scene-checks.json`, actual browser screenshots and pixel reports under `docs/agent/evidence/m07-01-visual/`. No DB migration; rollback the local commit and reinstall the prior offline lockfile. All backend contracts remain compatible.

## Loader, camera and entity lifetime (M07-02)

The loader accepts an AbortSignal, checks cancellation around asynchronous Pixi/asset initialization, and destroys its own application if canceled. Shared Assets textures stay cached; destroying one scene never destroys a texture used by another scene. Unmount removes the canvas and ResizeObserver and closes the room socket/listeners. Failed assets leave the independent room/seat controls available and explicitly report that rendering failed.

A fit camera scales and centers the complete world in its current viewport; ResizeObserver resizes the backing surface, with device resolution capped at two. No panning or speculative location is introduced. Sprites are keyed by viewer-authorized account ID and reused through same-context snapshots/deltas. Membership/epoch/account changes and disconnect clear old sprites. Hidden peers are never inferred from occupancy. Y position determines avatar depth. Current pose is only idle/sit plus reconnect opacity; original multi-frame animation is M07-03.

During an in-flight authoritative refresh, the layer is hidden and seat interaction disabled while sprite objects are retained for reuse. Transport loss and identity replacement remove that layer's entities. Old ACKs cannot publish over a newer operation or identity. Identity/catalog fetches are abortable; replaced identity clears cached self data and invalidates old operations. Disconnect also clears prior success messages. Camera/entity render occurs only on state/resize; the Pixi ticker remains stopped.

Browser lifecycle verification covers real peer join/seat/release/leave, stable creation counts on state changes, an idle interval without renders, resize, actual WebSocket closure and re-admission, identity replacement and route remount, failed asset loading, and unmount during a delayed real asset load. Entity counters are local diagnostics without account identifiers. They verify object lifetime behavior, not a JavaScript/GPU heap-leak bound or a low-end device FPS budget; M07-06 remains open.

## Original starter avatar (M07-03)

`avatar-art-generator.ts` authors original geometric pixel figures into a reproducible 512×768 SVG atlas: eight existing approved profile colors, casual and cafe-apron variants, idle/walk/sit/serve actions with four 32×48 frames each (256 cells). Runtime frame/palette metadata stays in `avatar-art.ts`. Idle blinks, walk strides, sit breathes/blinks and serve raises a tray with subtle steam. No imported images, music, characters or external resource URLs are embedded. `pnpm assets:avatars` generates the committed SVG/provenance; `pnpm assets:check` verifies exact output and SHA-256 against the generator. The provenance records dimensions, source, attribution review, owner rights decision and releaseApproved=false. This authorship record does not grant a distribution license or authorize public release.

`AvatarAppearanceSchema` limits the free starter core/palette/outfit; `AnimationStateSchema` limits action names. Room colors come only from server-filtered profile snapshots. Existing identity validation rejects unknown colors and client outfit/role fields; no entitlement, staff privilege or progression is created by clothing. The synthetic cafe selects a fixed bundled apron theme. Paid/earned cosmetics and ownership enforcement beyond these free defaults belong to M13.

The Pixi loader caches the shared atlas and creates cropped frame textures using nearest sampling. A finite state transition animates idle/sit then stops; idle has no perpetual frame ticker. Reduced-motion media preference stops transitions and presents a still frame. Unmount clears animation timers and cropped textures while retaining the shared cached atlas. Walk/serve artwork is exercised in `/worlds/sdk-sandbox/avatar-lab`; live authoritative walking remains M07-04 and hospitality service rules remain M11. The preview is local-only appearance exploration and sends no gameplay or profile changes. It includes explicit play/pause, manual frame stepping, color/outfit controls and reduced motion.

## Authoritative walking (M07-04)

The cafe's unchanged tile manifest now lives in `world-sdk/src/scene.ts` and is registered in the trusted world definition; the renderer reuses it without API importing Pixi. Definition validation rejects mismatched scene versions/seats. BFS visits bounded map tiles and returns a path of adjacent walkable tiles, including detours around tables. Solid/outside/unreachable destinations fail. No avatar-to-avatar collision or continuous city simulation is implemented.

Clients negotiate `motionVersion:1` when joining. The server includes movement only on opted-in connections, including per-connection filtered deltas for mixed old/new tabs. See ADR0010. `room.move` accepts only a destination and the usual membership/request envelope. Existing session/epoch/world/owner/rate/queue/idempotency guards apply; an overlapping walk waits and a seated actor must stand. Seat ownership is still atomic; its interaction point is resolved from trusted geometry and reached on a server-approved path. The internal path is timed even for a legacy seat claimant. Release and final disconnect freeze at the last complete tile; ordinary grace/rejoin behavior remains intact.

Visible entities interpolate along approved segments using the snapshot clock plus local monotonic elapsed time. Walk frames run only while moving; the avatar settles to idle/sit, then the renderer stops. Reconnect/identity changes clear stale trajectories. Hidden and blocked peers receive no motion projection. A failed move is followed by an authoritative snapshot before interactive state resumes. Canvas taps and labeled keyboard destination buttons use the same command. There is no movement persistence, speculative client position input or per-tick server broadcast.

## Accessible cafe controls (M07-05)

All current cafe capabilities (entry/exit, walking, seat claim/release) have labeled native controls outside the canvas, including when artwork fails. The sandbox declares no hospitality/service capability; those future controls must follow the same keyboard/fallback contract when M11/world integration adds them. The canvas is hidden from accessibility APIs behind a descriptive floor-plan image role; an independent participant list and polite connection/visit messages convey authoritative state.

Skip/back links target visit controls. Manual entry focuses the walking heading so Tab reaches actions; leaving restores the entry button. Network resync/reconnect does not request focus. Unknown occupancy displays a dash. Seat reservation is announced separately from walking to the seat, and the movement deadline updates text once on arrival; it never grants authority to client timing.

The room exposes a per-visit reduced-motion checkbox, initially honoring the operating-system media preference. An explicit choice overrides that preference for the mounted page and is not stored or transmitted. It stops animation timers and presents still destinations while the server's travel time remains enforced. Both the scene and art preview are silent. Small text colors were darkened after measured baseline ratios below4.5. Buttons retain at least44px height, responsive columns and visible focus outlines. Browser tests check computed text/background contrast, keyboard entry/action/exit focus, actual fallback controls and mobile overflow/targets. This is scoped evidence, not a full WCAG or assistive-technology certification.

The mobile audit found Pixi's automatic offscreen touch accessibility hook (a nominal1px button, computed16×6). The renderer now disables automatic canvas Tab activation and hides that public `hookDiv`, leaving the native labeled alternatives as the keyboard interface. This fixes an unnamed duplicate focus target without removing application controls. Final evidence: `m07-accessibility-checks.json`,28 browser cases and preserved computed contrast/geometry reports; minimum sampled small-text contrast5.7288 and minimum button target44px.

## Loading/cache and local budgets (M07-06)

The model root no longer requires Pixi; the portal dynamically imports the exact public `@virtual-city/pixi-scene/renderer` entry. Generation-only artwork code is separate. The generated atlas URL carries its SHA-256 revision, gets immutable HTTP caching, and is reproduced alongside provenance and bundled metadata by `assets:check`. Private deep imports remain prohibited. See ADR0011 and [actual local measurements and limitations](SCENE-PERFORMANCE.md). Final30 desktop/mobile E2E cases include CPU/network/readiness, actual warm cache, idle work and repeated SPA lifetime checks. M07-01..06 are verified at local synthetic/starter engine scope; W1 safety, travel and real-world activation remain incomplete.
