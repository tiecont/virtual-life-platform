# Native account custody — N10-03

Implementation: [ADR0130](../adr/0130-native-device-custody-and-one-use-tickets.md). Acceptance and source hashes are recorded separately in the vNext state/evidence index. Proposed or interrupted commands are never counted as a successful gate.

The normal mobile bundle remains a logged-out local preview. Native server routes require `NATIVE_AUTH_ENABLED=1` and a stable independent64hex `NATIVE_AUTH_KEY` supplied privately. Default server config disables them. Android debug builds need a fixed HTTPS origin; release builds currently hard-disable native login. Web signed cookie,exact Origin,CSRF and old protocol contracts remain. No production migration,distribution,store or public-world activation is implied.

`NativeSessionCustodyPort` provides public identity,account settings,devices,revoke/logout and short one-use socket tickets. Refresh/access/core/internal grant credentials never cross its JavaScript boundary. Android owns encrypted refresh custody in noBackupFilesDir with nonexportable Keystore AES-GCM. A bounded process-wide serial queue prevents overlapping refresh/rotation; rotation is persisted/read back before success. Restart restores through refresh. A lost refresh ACK,corrupt/unavailable storage or uncertain upgrade fails closed and can require sign-in again. Offline logout always removes local custody and explicitly reports whether remote revocation was confirmed. Java immutable strings cannot be securely zeroed. Emulator coverage does not qualify hardware-backed custody,physical performance or a supported-device floor.

The account panel is opt-in with `VITE_VLP_NATIVE_AUTH=1` and is separate from the unauthenticated room preview. Its native general HTTP port allows only GET/PATCH own profile/privacy. The missing native room safety/business adapters are still a gameplay gate. iOS has no fallback store; Keychain/build/Simulator/physical qualification remains N14 and requires Apple tooling/access.
