# Controlled procedural renderer loading and heap

N06-11 has a separate Chromium harness, implemented as `pnpm test:scene3d-loading`. The command builds the explicit synthetic workload mode, then runs the harness. A command in this document is an implementation entry point, not evidence that it passed. Actual outcomes live in the vNext audit/state evidence.

[Protocol v1](../../tests/renderer-workload/LOADING-PROFILE-v1.json) is locked before measurement. Each Low/Balanced desktop/landscape tier uses ten cold/warm pairs. Cold means a fresh browser context with HTTP cache cleared, not a cold OS/GPU/browser process. Warm is a normal reload in the same context with actual CDP asset-cache evidence. Loopback serves gzip with exact lengths, immutable assets and uncached HTML; CDP fixes latency/throughput and CPU slowdown. Network response/cache flags, Navigation/Resource Timing, raw samples, p75 nearest-rank, GPU, source/bundle/profile/budget hashes and screenshots are retained. No slow sample is trimmed or silently retried.

The initial `quality` query selects the synthetic renderer tier before construction; an absent value preserves Low and invalid values reject. This only affects the explicit workload build. Ready means twenty synthetic actors and two animation frames. It excludes real account/travel/admission, network API and interaction correctness, and is not a full game startup claim.

A separate unthrottled context measures Balanced heap after two warm recreations and twenty measured recreations. Each active sample gets two externally invoked CDP collections with fixed idle time. `Runtime.getHeapUsage.usedSize` is compared against the same active warm baseline using the original `max(16MiB,20%)` rule. Every teardown must leave zero actor leases and canvases. Post-stop heap, embedder and backing storage are separate diagnostics. Missing GC/heap evidence fails closed. This is not driver residency, native RSS or twenty authenticated visits.

The original [workload profile](../../tests/renderer-workload/PROFILE.json), [3D budgets](../design/vnext/animals-3d/budgets-v1.json), Android spike and earlier failures remain unchanged. Embedded procedural geometry has no separately downloaded final art: the 1500ms art-wait and 8/24MiB final catalog gates remain **NOT_QUALIFIED**, even if JS startup passes. Software GPU loading/heap does not override earlier frame-time failures. Packaged Android local assets need a separate process/cache protocol; physical thirty-minute/thermal/battery and iOS remain separate.

The harness writes a unique private `artifacts/vnext/n06-11/loading-v1/browser-*` directory. It never writes into frozen workload/serve/native evidence, starts an AVD, installs an APK or contacts an external service. After measuring, restore normal generated web output with `pnpm --filter @virtual-city/mobile build` and run `pnpm mobile:bundle:smoke`; this browser-only command does not replace installed Android assets.
