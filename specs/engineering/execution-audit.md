`master-campaign-v4` recovery state. The development plan identifies VL-190 as
the existing harness. The isolated campaign worktree protected active development.

qualification.

## Comparative evaluation protocol

Freeze the exact committed source, task inputs and acceptance for all variants.
Use separate worktrees for each run, equivalent granted capabilities, and
independently grade the evidence. Use an existing authorized session. Record its
actual platform, model alias, mode and enforced privileges. Leave unavailable
measurements `UNKNOWN` and unexecuted variants `NOT_RUN`.

| Variant | Instruction and controls |
| --- | --- |
| A Existing approach | Give the same task with the former VL-190 startup and runbook. Retain the same approvals and machine prerequisites. |
| B Universal | Give the short task or resume prompt and the contract entry. Retain the same environment as A. |
| C Lower-cost Universal | Give the identical prompt and acceptance with an available lower-cost alias. Compare only capabilities that overlap. |

Use the short prompts in the contract. Include the following cases in both
single-agent and any authorized multi-agent run.

| Case | Prompt subject | Independent acceptance |
| --- | --- | --- |
| Local review | Review the frozen migrations and release source policy | Exact clean revision; all five existing workflow steps pass; evidence SHA-256 verifies; altered digest is rejected. |
| Gameplay change | Plan a change to typed gameplay configuration under `packages/contracts/src/gameplay-config.ts` | Resolves native rule authority, bundle validation, Rust workspace proof and dependent Nest effect; no balance fallback. Require implementation/regression evidence when running the implementation variant. |
| Visual intake | Identify the gated next stage for a new flagship humanoid and detached Pet accessory | Correct distinct skills; authentic current source and owner gates; identify missing approved artifact, access or cost before proceeding. Actual visual acceptance requires owner review of qualified artifacts. |
| Interrupted task | Resume the same candidate after its first check from a portable checkpoint | Restore state from the pinned revision; reject malformed or stale evidence; finish the pending work without the conversation. |

For each model run record first-attempt completion, retries and reasons, owner
interventions, wall time, tool calls, actual evidence and whether the required
output was accepted. Keep the operational measurements separate from the
reviewer's judgment. Report tokens and cost only if trustworthy provider data
are available for that exact run. Compare the same scope and acceptance results
before drawing conclusions about quality parity.

The local evaluation exercises route discovery, impact, gate selection,
capability logic and actual workflow/evidence retrieval. The VL-190
`benchmark.mjs` additionally compares existing raw commands and bounded
workflow projections and measures local elapsed time and visible bytes. The
automated harness test suite covers checkpoint corruption, missing evidence and
invalid inputs. These tool-level cases can support future comparisons. The
model variants and cross-platform compatibility still need direct execution.
